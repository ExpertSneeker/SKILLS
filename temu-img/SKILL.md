# TEMU 图片工作流

## 开工前检查

缺一项就先报错，不要硬做或凭空补信息。

- [ ] 有需求表
- [ ] 有产品尺寸
- [ ] `2560px拍摄图/_manifest.json` 存在，且映射中至少有一张产品实拍图
- [ ] 有输出类型：主图 / 副图 / 颜色图 / SKU 图 / 尺寸图 / 卖点图
- [ ] 已确认采用“主 Agent 规划、所有图号全局串行生图、每个 direct 由全新单版生成 Subagent 调用一次生图工具；同一图号三版齐后由一个全新验收 Subagent 合并审核和选片”
- [ ] 已确认 manifest 产品实拍查看显式调用自定义 Subagent `temu_image_inspector`，需求表及其他图片由主 Agent 查看和分类
- [ ] 已确认 `2560px拍摄图/_manifest.json` 登记的实拍图由 `temu_image_inspector` 执行 `view_image`，需求表及其他图片由主 Agent 执行 `view_image`
- [ ] 已检查 VI 手册、产品图、面料图、色卡图、颜色代号图及存在时的参考图等素材可读

## 拍摄图输入门禁

- 只有 `2560px拍摄图/_manifest.json` 存在、非空时，才可继续本 Skill。
- 本 Skill 只读取映射中登记的目标文件；禁止读取、查看或传递原始拍摄图路径。
- 本 Skill 后文的“产品实拍图”“产品实拍”“实拍输入”和“产品垫图”均指当前任务 `2560px拍摄图/_manifest.json` 中登记的目标文件，不指原始拍摄图。

## 图片输入分类

- 实际生成输入：manifest 产品实拍、颜色/面料、结构细节、插入或辅助素材；继续按实际路径显式传入当前生图工具，并在提示词中使用连续的 `Image N`。
- 反推专用参考图：只会出现在需求表中，指其中带产品、仅用于版式或场景参考的图片；只允许主 Agent 查看、确定并反推版式、区域比例、场景、背景、道具、光线、视觉层级和展示数量，禁止传给任何 Subagent 或当前生图工具。
- 反推专用参考图中的产品外观、颜色、面料、产品结构、Logo、品牌均不得提取；现成英文和标题/副标题信息层级仅按设计模块的文案规则提取。展示的产品数量只作为构图信息；需求表明确的 `N PC` 或售卖数量始终优先，且不得将反推数量记为商品规格。
- 反推专用参考图不是开工必选项：有则按生成模块分配给不同 direct 使用反推结果；没有则由主 Agent 独立规划三版，不得因此阻塞。

## 生图工具选择器

- 当前任务明确指定生图工具时使用指定工具；如果 `references/<工具名>.md` 存在，先完整读取该适配器，否则读取该工具自身 skill。
- `豆包`、`豆包生图`、`Seedream`、`Seedream 5.0 Pro`、`seedream5.0pro` 均指 Seedream 5.0 Pro：完整读取 [seedream.md](references/seedream.md)，并直接运行 `scripts/seedream5_pro.py`。用户明确“用豆包生成”时不得转交其他生图工具。
- 未指定生图工具时使用 `$imagegen`，并完整读取 [imagegen.md](references/imagegen.md)。
- 工具只选择一次，后续统一称“当前生图工具”。

## 设计步骤

严格按以下顺序执行，缺一不可。

1. 规划图片与编写提示词前的步骤
    - 完整读取 [design-and-prompt.md](references/design-and-prompt.md)。
    - 若用户或需求表明确支持定制，或者尺寸为连续可选区间时，完整读取 [custom-product.md](references/custom-product.md)。
    - 产品实拍图只按拍摄图输入门禁处理；其他不可读取的 JPG/JPEG/PNG 参考图片必须先转码或用其他工具打开。
2. 确认 `2560px拍摄图/_manifest.json` 映射非空后，显式调用一个全新的 `temu_image_inspector` 查看映射中的全部产品实拍目标文件；主 Agent 根据返回结果锁定产品身份、颜色、纹理、结构、比例和禁止偏离项。
3. 主 Agent 读取 `.xlsx/.xls` 需求表中的需求、参考图、英文文案、尺寸、输出类型、颜色/SKU 等信息，识别 WPS `DISPIMG` 单元格图片并亲自执行 `view_image`；结合已锁定的产品基准，确定需求表中哪些图片是反推专用参考图。需求表以外的颜色/面料、结构细节、插入或辅助图片也由主 Agent 查看并确定角色。
4. 从需求表取得并理解产品尺寸，按人物、家具、手持、宠物、儿童或使用场景校验比例，并按设计模块处理需求表与平台规范的优先级；
5. 按设计模块分别处理产品颜色展示和色块素材缺失，不得凭空编造颜色。
6. 主 Agent 完成需求表图片和除了`2560px拍摄图`之外的其他图片的查看与分类。
7. 组织主 Agent、单版生成 Subagent 与独立验收 Subagent、准备输入或开始生成前，完整读取 [generation-workflow.md](references/generation-workflow.md)。
8. 已确定的反推专用参考图存在时先形成反推结果并按 direct 分配，不存在时自行规划三版；确定各 direct 的场景、构图和版式后，为每个出现产品的 direct 从 manifest 产品实拍中分别选择唯一 `edit target`，再确定其他实际生成输入及其图片角色。三个 direct 可以使用同一 `edit target`，也可以分别使用不同实拍，不得强制统一。首次生图前，按设计模块的提示词编写步骤与格式，完整预写 `direct01`、`direct02`、`direct03` 三版提示词并完成生图前检查；调用前按选择器读取对应适配器或工具自身 skill，再使用当前生图工具进行整图图生图。
9. 每张图片生成 `direct01`、`direct02`、`direct03` 三个候选；三版提示词必须有明确调整，并保存到当前工具规定的直接生成路径。所有图号共用一个生图槽，同一时间只允许一个单版生成 Subagent 调用生图工具。
    - 每次生成前按当前工具适配器或自身 skill 建立调用记录，每次只接受可唯一归属本次调用的一张源图。
    - 每张结果只执行生成模块的技术门禁；通过后标记 `CANDIDATE` 并继续下一版，不做逐张独立产品细节验收。
    - 三版齐后由一个全新验收 Subagent 合并比较，输出 `ELIGIBLE`、`HARD_FAIL`、警告、排名和唯一 `SELECTED`。
    - 三版通过技术门禁但合并验收均为 `HARD_FAIL` 时，最多生成一次 `repair01`；仍不合格则跳过该图号、继续其他图号，并将整套标记为 `PARTIAL`。
10. 当前工具或 Session 中断、超时或未稳定进入下一次生成时，不得标记完成；核对直接生成目录的文件数量、大小和时间戳，从缺失图型及序号继续补齐。
11. 保存 FINAL 或执行整套终验前，完整读取 [delivery.md](references/delivery.md)；使用合并验收选中的 `SELECTED` 候选，局部修改或文字覆盖只保存为临时检查对比稿。
12. 按交付模块完成尺寸、输出类型映射、路径和命名；最终图不得只留在工具默认目录或临时目录。
13. 使用交付模块的 FINAL 与整套终验清单，确认符合需求表、TEMU 平台规范、美国市场风格和本工作流。
