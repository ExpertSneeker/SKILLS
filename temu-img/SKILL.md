## 图片设计原则

- 应该突出卖点，符合 TEMU 美国站购物场景：清楚、直接、真实、产品识别强。
- 文案严格按照需求表中的英文文案进行设计，确保信息传达准确。如果有拼写、单复数、明显语法或单位格式错误，只允许做最小修正，保持原意不变；不得改卖点角度、不得补充未提供信息、不得夸大性能。如果需求表中没有文案并且没有说明无文字，但是参考图中有文字的，参考图中的文字可以作为文案参考。
- 图片内不允许出现中文。
- 整套图片的风格、配色、元素、字体保持一致，确保视觉统一。参考图只参考版式、氛围和视觉语言，不得照搬人物容貌、文案、图标或品牌元素。
- 场景中人物的年龄、体型、家庭环境、家具尺度、使用方式和审美，要尽量符合美国目标市场预期。抱枕、坐垫、床品、家居用品、宠物用品、婴童用品等必须按实际尺寸和使用对象校验比例。
- 如果产品为座垫等需要放在沙发/长凳等载体的用品，如果是产品尺寸可定制，则产品尺寸必须与载体一致，如果是固定尺寸的产品，则必须选择与产品尺寸匹配的载体进行场景设计，避免出现产品过大或过小的情况。总之产品的尺寸必须与载体一致，载体上面不要留空。要在提示词中体现这个要求。

## 设计步骤
> 严格按照以下步骤进行设计，缺一不可。必须使用 `$imagegen` skill 进行图生图，必须提供产品实拍图给生图模型。除非需要局部修改、文字覆盖、尺寸调整或文件保存，不使用其他工具替代生成设计。

1. 同目录下寻找 VI 手册 / brand guide / logo 规范（如果有则必须严格遵守，包括配色、字体、logo、版式等）和产品实拍图（必须）。对于不可读取的 JPG/JPEG/PNG，不要跳过，要想办法转码或使用其他工具打开，确保正确使用每一个参考图片。
2. 参考需求表（`.xlsx/.xls` 优先）中的需求、参考、文案、尺寸、输出类型、颜色/SKU 信息和禁用信息。需求表中的要求为最高优先级；如果与平台规范冲突，以平台规范为准并向用户说明。
3. 在需求表中获取产品尺寸；如果没有产品尺寸，先向用户询问。必须理解这个尺寸意味着什么，并在画面里按人物、家具、手持、宠物、儿童或使用场景比例校验产品大小。
4. 检查同目录是否有面料颜色图、色卡图、颜色代号图或按颜色代号命名的图片文件。图中产品颜色优先使用产品实拍图中的颜色；如果制作颜色展示副图且找到了对应面料颜色图，则将产品改为相应面料颜色并放入颜色展示页面；如果没有面料图但需求表或文件名中有颜色文字，则按颜色文字将产品改为对应颜色；如果有颜色展示页面需求，但没有颜色编号、颜色文字或面料图，则产品颜色展示区域留白，只生成版式和文案内容，不得凭空编造颜色。另外要求放置色块图但是需求表中的颜色编号没有完全找到实际图片的，使用已有的颜色图进行代替，后续由用户手动加上。
5. 需求表中有可能是 WPS 的 DISPIMG 单元格图片，要确保正确识别这些图片，不得漏读嵌入图片。
6. 首次生图前必须建立“产品/面料基准”：明确哪张图是强制产品/面料输入，记录必须保持的颜色、纹理、结构、比例；如果参考图或场景氛围与实拍颜色冲突，以产品/面料实拍图为准，并在提示词中写明禁止偏离项。
7. 使用 `$imagegen` skill 进行图生图，严格按照 `生成图片注意事项` 部分执行。参考图只进行风格与板式参考，必须挑选合适的产品实拍图作为强制产品输入垫图；如本文件夹或需求表中有关键 JPG 参考图，也可以选择与当前图片卖点最相关的 JPG 一并作为参考输入。提示中必须明确：“保留产品结构、面料、颜色和比例，不重设计产品”。因为已经提供产品图作为垫图，提示词中不得描述产品细节、结构、面料纹理、缝线、厚度、形状等，不用文字重新定义产品外观；只写场景、版式、画面文字、比例要求和保留要求。
8. 每张图片至少生成三次，三版提示词必须有明确调整，不能使用完全相同提示词。三版直接生成结果都保存到 `制作规范中的直接生成图片路径`。
8.1 每次生成 direct01/direct02/direct03 前，按 `imagegen 输出保存防串图规则` 建立调用记录；每次只接受本次调用可唯一归属的一张源图。
8.2 TEMU 所有 direct 图必须为正方形构图；非正方形、来源不明、内容不符或混入其他语言/产品的文件一律作废，不计入三版。
8.3 三版直出图必须逐张写入 `_imagegen_manifest.jsonl`，并确认源文件哈希、目标文件哈希、尺寸和提示词编号完整。
9. 若 `$imagegen`/会话中断、超时，或工具没有稳定进入下一次生成，不得把该图标记为完成；先核对直接生成目录中的文件数量、大小、时间戳，每生成一张立即保存到 `./output/gpt-images-2-direct`，并从缺失的图型和序号继续补齐三版。
10. 从三个版本中优先选择产品还原最准、比例最合理、英文文字错误最少、构图最稳定、最符合 TEMU 美国站风格的版本。允许局部修改或准确英文文字覆盖，但仅保存修改后版本到 `./output/temp` 作为后续检查和对比稿；最终交付不得使用本地排版或文字覆盖。
11. 完成后按输出类型调整尺寸：所有 TEMU 图片最终尺寸为 `1000*1000`。需求表中写作“详情、详情页、SKU、颜色图、规格图、卖点图”的内容，一律按副图主题处理，除非用户另行指定。最终交付图保存到 `制作规范中的最终交付图片路径`，不允许只留在 Codex 默认目录或临时目录。
12. 进行自我检查，确保设计符合需求表、TEMU 平台规范、美国市场风格和本文件的设计原则。

## Session 与 view_image 规则

### 主 Session 职责
- 主 Session 负责读取需求表、拆分整套图片任务、统一风格、配色、字体、尺寸规范、输出顺序。
- 主 Session 不负责连续生成所有图片。
- 主 Session 必须输出每张图的用途、文案、卖点、参考图清单。

### 子 Session 职责
- 每张图片必须使用独立子 Session 生成。
- 一个子 Session 只对应一个图号。
- 子 Session 结束后，将最终提示词、参考图角色、输出路径回写主 Session。

### view_image 强制规则
- 所有参与 imagegen 的图片必须先执行 `view_image`。
- 未执行 `view_image` 的图片不得声称已提供给模型。
- 子 Session 中必须记录图片角色。

### 图片角色系统
> 根据需求来选择，但必须明确记录每张图的角色。
- Image 1(产品图/实拍图) = edit target / base image
- Image 2 = primary product identity reference
- Image 3 = fabric/material reference
- Image 4 = detail reference
- Image 5 = layout reference
- Image 6 = style reference
- Image 7 = scene reference
- Image 8 = insert/supporting asset

### 上下文污染规则
- 禁止沿用上一张图的图片编号。
- 禁止把上一张图的版式、文案、场景自动带入当前图。
- 出现跨图污染时，该版本作废，不计入三版直出。

## 生成图片注意事项

- `$CODEX_HOME/generated_images` 是全局生成目录，可能混入其他 session、其他产品、其他平台或其他语言的图片；禁止按“最新时间”“最新文件”“最大文件”猜测复制。
- 每次调用 `$imagegen` 前，必须记录：本次任务ID、平台、产品名、图片编号、版本号、目标文件名、提示词编号、调用开始时间，并对全局生成目录做一次文件快照。
- 调用结束后，优先使用 `$imagegen` 本次返回的明确源文件路径。若工具未提供明确路径，只允许通过“调用前后快照差异”定位源文件；且候选文件必须唯一。候选不唯一、路径不明、时间异常、尺寸异常或内容不符时，必须判定为污染风险，不得复制为直出图。
- 禁止把来源不明的图片计入“三版直接生成”。污染文件如已被复制，必须移入 `./output/temp/rejected-imagegen` 或在清单中标记为 rejected，不得进入最终交付。
- 每张直出图复制后必须立即记录源文件绝对路径、源文件 SHA256、目标文件 SHA256、尺寸、复制时间、提示词编号和校验结果。
- 直出图必须与当前产品、平台语言、目标尺寸/比例一致；如出现其他产品、其他品牌、其他语言、其他 session 内容，立即作废并重新生成。
- 生成的场景图如果带有产品，必须确保产品在场景中的尺寸符合实际尺寸，不能过大或过小。抱枕、坐垫、床品、家具配件、宠物用品、婴童用品等必须参考人物、家具、床、椅子、宠物或儿童体型比例校验。
- 必须使用 `整张直接图生图` 的方式生成图片，包括图中出现的英文文字。如果文字出现明显错误，则直接重新生成；如果多次生成后文字仍有错误，则跳过此图片。允许局部修改或准确英文文字覆盖仅保存到 `./output/temp` 作为检查对比稿；最终交付绝对不允许使用本地排版或文字覆盖方式制作，且须保留每张图的直接生成版本。
- 生成图片时，如果图片中包含产品、面料、纹理、结构、颜色等需要实拍支撑的内容，必须选择相应的单张或多张产品图作为参考进行图生图，禁止文生图凭空生成产品。
- 生成的图片绝对不要改变产品细节、结构、面料、颜色和比例。不得把方形改圆形、改变缝线/边缘/厚度、增加不存在的配件或重设计产品。
- 提示词禁止用文字定义产品外观，不得描述产品，例如颜色/细节等；在提示词中使用类似"参考图1"的方式等来代指产品。
- 美国站生活方式场景应真实、易理解，优先使用与产品价格带和用途匹配的家庭、户外、车内、办公、宠物或儿童使用场景。
- 参考图只可参考风格、氛围和信息组织版式，不得照搬他店人物或品牌元素。
- **验证图片是否可用的环节必须使用独立的Subagent进行检查，不允许使用主Session或者生图的Agent**
- 如果需求表中要求生成每个颜色一张图的场景或者SKU图，只生成一个颜色的即可。

## 提示词产出格式
> 每张图使用以下结构整理提示词，可做略微调整，中括号与中括号内的内容不要保留。
> **参考规则** 不允许使用参考图中的产品，只参考版式/场景和人物氛围/构图，不允许照搬人物。

```text
【图片比例】
1:1正方形构图

【画面目标】
这张图要解决的销售任务：吸引点击、解释功能、展示材质、证明尺寸、突出定制、表现舒适感等。

【画面构成】
主体产品位置、人物(默认欧洲年轻女性,如有具体需求则按照需求表来)/场景、背景、道具、文字区域、版式层级。

【产品输入】
写明使用哪些产品实拍图作为图生图垫图，是否加入本文件夹或需求表中的参考图。必须写明“保留产品结构、面料、颜色和比例，不重设计产品”。不要在提示词中描述产品细节，产品细节以垫图为准。

【颜色/面料】
是否为颜色展示副图；是否找到面料颜色图、色卡图、颜色代号或颜色文字；只描述改色依据和展示版式，依据不足时颜色展示区域留白，不描述或重构产品细节。

【view_image 输入记录】
列出当前 Session 中已执行 view_image 的图片及角色：
- Image 1: edit target
- Image 2: product identity reference
- Image 3: detail reference
- Image 4: layout reference
根据实际情况增减。

【文案】
必须包含需求表中出现的文案，不要夸大卖点。不得出现中文、乱码或新增卖点。

【风格】
TEMU 美国站电商图风格，清楚、真实、产品优先，符合美国消费者购物场景。
版式/配色/字体风格要使用本系列图的统一风格，此风格在第一次生成时根据产品与需求来确定。

【如果图中有产品出现在场景里则加上这条固定提示词】
场景充满生活感，专业电商摄影风格，专业打光，保持产品的透视角度正确，产品的光影自然的融入场景中，looks like a premium furniture brand catalog photo
```

## 制作规范

- 所有 TEMU 图片最终尺寸为 `1000*1000`
- TEMU 不使用详情页长图作为本工作流的独立输出类型；需求表中的详情、详情页、SKU、颜色图、规格图、卖点图都按副图处理
- 产品尺寸单位标注优先使用美国市场常用的 `inch`；需求表已有明确单位时按需求表执行，但图片内表达必须自然、统一、易读

**路径规范**
- 直接生成图片保存路径 `./output/gpt-images-2-direct`
- 最终交付图片保存路径 `./output/final`
- 临时修改图片保存路径 `./output/temp`
- imagegen 输出清单路径 `./output/gpt-images-2-direct/_imagegen_manifest.jsonl`
- 污染/作废图片隔离路径 `./output/temp/rejected-imagegen`
- 在 Windows 中文目录中处理图片/表格时，必须使用 Unicode 安全的绝对路径和文件 API；不要通过会丢失编码的管道或通配符把中文文件名传给脚本。如出现 `????` 路径，先修复读取方式再继续

**命名规范**
- 直接生成图：`产品名_图类型_序号_direct01.png`、`direct02.png`、`direct03.png`
- 最终交付图：`产品名_图类型_序号_v01.png`
- 示例：`custom_sofa_cushion_副图_01_v01.png`

## TEMU 平台规范

**主图**
- 尺寸为 `1000*1000`。
- 产品不得被裁切，不得通过夸张透视或错误参照物误导尺寸。

**副图**
- 尺寸为 `1000*1000`。可做场景图、卖点文案、结构说明、尺寸说明、材质细节、定制选项、使用前后对比、颜色选择、SKU 展示或规格展示。
- 副图信息可以比主图更完整。
- 颜色、图案、尺寸、数量或定制选项展示必须准确，避免让用户误解实际可选范围和售卖内容。
- 尺寸图必须结合实际产品尺寸和常见参照物，避免把产品做得过大或过小。

**合规限制**
- 禁绝对化、无依据或易误导的词汇，例如 `best`、`#1`、`perfect`、`100% safe`、`guaranteed`、`forever` 等，除非需求表提供可核验依据且平台允许。
- 禁医疗、治疗、矫正、疾病改善、功效暗示，除非有明确资质和需求表依据。
- 禁认证标识乱用。没有授权或需求表依据时，不得添加 `certified`、`approved`、`official`、`patented` 等表达。
- 禁未经授权使用他店图片、商标、logo、角色。
- 如果平台规则、需求表和用户口头要求冲突，先暂停并说明冲突点，不要硬做.
