# 通用生成流程

本文件是三版生成、技术门禁、合并验收和补生上限的唯一规则源；工具适配器只补充调用与恢复差异。

## Agent 职责

**主 Agent**

- 锁定每个图号的销售任务、产品基准和必需事实；形成并分配反推结果、确定各版场景与构图后，再为每个出现产品的 direct 分别选择唯一 `edit target`，确定其他输入路径并编写三版提示词。三个 direct 可以复用同一底图，也可以使用不同底图。
- 显式调用 `temu_image_inspector` 查看 manifest 产品实拍并根据返回结果锁定产品基准；需求表及其他图片必须由主 Agent 查看和分类。
- 将需求表中带产品的版式或场景参考图仅作为反推专用参考图，完成反推和内部来源记录；不得把该图路径、名称、图片编号或对该图的引用写入生成提示词或派发给生成 Subagent。
- 只负责派发、技术门禁、记录和推进流程，不直接调用生图工具，也不替代合并验收 Subagent 选片。
- 所有图号共用一个生图槽；同一时间只允许一个生成 Subagent 调用生图工具。验收、素材读取和其他非生成 Subagent 不计入生图上限，也不受本文件额外限制。
- 每个图号只执行三版生成、一次合并验收和最多一次 `repair01`；无合格图时标记 `SKIPPED` 并继续其他图号，整套状态为 `PARTIAL`。

**产品实拍查看 Subagent (`temu_image_inspector`)**

- 使用一个全新的 `temu_image_inspector`，只查看 `2560px拍摄图/_manifest.json` 登记的全部目标文件，逐张返回绝对路径和产品可见事实；主 Agent 据此锁定产品身份、颜色、纹理、结构、比例和禁止偏离项。
- 产品基准锁定后，主 Agent 亲自查看需求表中的全部图片和需求表以外的颜色/面料、结构细节、插入或辅助图片等，记录路径、来源位置、可见事实、分类、理由和适用图号，并冻结分类。

**生成 Subagent**

- 每个 direct 使用一个全新 Subagent；只接收当前冻结提示词、产品基准、该 direct 自己的唯一 `edit target`（目标画面不出现产品时不设置）、其他实际生成输入的准确路径和唯一目标文件名，只调用一次当前生图工具。
- 在自己的上下文中重新查看全部实际输入，按当前顺序记录角色，完成来源登记后退出。
- `direct01` 通过技术门禁后立即生成 `direct02`，不等待产品细节验收；`direct02`、`direct03` 同理。
- `repair01` 也使用全新 Subagent，且不得把任何 direct 当作输入或上下文。

**合并验收 Subagent**

- 三个 direct 均成为 `CANDIDATE` 后，为当前图号使用一个全新验收 Subagent 一次比较三版。
- 重新查看三张候选，并按候选与 direct 的映射分别查看各自的 `edit target`，同时查看当前销售任务必需的产品、面料或结构素材；不同候选可以对应不同 `edit target`，不接收或查看反推专用参考图。
- 为每版记录硬错误、警告和排名；硬错误版本标记 `HARD_FAIL`，其他版本标记 `ELIGIBLE`，排名最高者唯一标记 `SELECTED`。
- 主 Agent、生成 Subagent 自检或来源记录不能替代本次合并验收。

## view_image 与图片角色

- 所有参与生图的图片必须先执行 `view_image`；产品实拍只允许使用 `2560px拍摄图/_manifest.json` 登记的目标文件，禁止查看或传递原始拍摄图。
- 每个生成 Subagent 只对当前 direct 的实际生成输入连续编号，不沿用其他 direct 或 Session 的编号。目标画面出现产品时必须且只能有一个 `edit target`；其他角色为 primary product identity、fabric/material、detail/structure、insert/supporting asset。不同 direct 的 `edit target` 路径互不绑定。
- 输入格式: `Image N = 图片身份`
- 格式举例: `Image 1 = edit target`
- 提示词中的 `Image N`、适配器输入顺序和实际文件顺序必须一致。

## 反推专用参考图

- 反推专用参考图是可选项；没有时不得阻塞，主 Agent 根据当前图号的销售任务独立规划三个 direct 的场景、构图和版式。
- 反推专用参考图只会出现在需求表中。只有主 Agent 在产品基准锁定后亲自查看并冻结分类，图片才确定为反推专用参考图；不得将其列入实际生成输入、连续 `Image N`、适配器参数或验收输入。
- 需求表中带当前产品或竞品产品、用途仅为版式或场景借鉴，且不承担当前产品身份、颜色/面料、结构细节或插入素材角色的图片，可分类为反推专用参考图；需求表以外的图片不得分类为反推专用参考图，无法确定角色时分类为不使用。
- 只反推版式结构、区域比例、场景、背景、道具、光线、视觉层级、白底或人物是否出现，以及展示数量；不得提取竞品产品外观、颜色、面料、结构、Logo、品牌；现成英文和标题/副标题信息层级仅按设计模块的文案规则提取。
- 锁定产品真实性基准后、确定各 direct 的其他实际生成输入前，将允许提取的内容改写为独立、具体的反推结果。生成提示词不得提及反推专用参考图、其路径、名称或图片编号，也不得出现“参考/忽略该图产品”等指令。
- 主 Agent 在提示词之外保留 `【内部参考反推记录】`，逐张记录绝对路径、分析角色、反推结果中的版式/场景/展示数量，以及产品数量、尺寸、形状、结构、颜色、面料和文案等商品规格的真实来源。该记录不得写入提示词文件或派发给生成、验收 Subagent 和生图工具。
- 同一图号有多张反推专用参考图时，优先让不同 direct 使用不同参考图的反推结果，每个 direct 最多分配一张。恰有三张时一版一张；多于三张时由主 Agent 按销售任务匹配度和三版差异化价值选择三张；少于三张时可重复使用参考图。分配结果写入内部记录，数量不匹配不得阻塞。
- 反推的展示数量只用于构图；需求表明确的 `N PC` 或售卖数量始终优先，且不得将反推数量登记为商品规格。

## 产品与提示词基准

- 首次生图前锁定产品身份、颜色、纹理、结构、比例、售卖数量、真实尺寸和载体适配；定制产品同时锁定形状能力及结构选项依据。
- 产品身份和商品规格只依据 manifest 产品实拍、需求表、用户确认及已声明的实际生成输入；反推专用参考图的反推结果只控制场景、版式和文案信息层级，不得成为商品规格或未经核实卖点的依据。
- 三版共同的产品身份和商品事实基准不变，只调整各自声明的场景、构图或版式。每个 direct 的 `edit target` 属于该版实际输入，不属于三版共同基准；底图可以相同或不同，但不得因此改变产品身份或商品事实。
- `repair01` 只针对合并验收发现的共同硬错误调整提示词，并重复全部不可变项。

## 生成与技术门禁

1. 调用前按适配器完成输入数量、路径和格式预检；预检失败时先修正，不调用工具。
2. 三个 direct 分别由三个全新生成 Subagent 全局串行生成，每次只接受一张可唯一归属的结果。
3. 主 Agent 在每次调用后只执行下列技术门禁，不派独立验收 Subagent：
   - 文件已保存到规定路径，可正常读取且为 1:1 正方形。
   - 源路径、源/目标哈希、尺寸、提示词编号和来源记录完整且唯一。
   - 结果属于当前任务和当前产品，无其他 Session、产品或上一图内容污染。
4. 通过技术门禁的结果标记 `CANDIDATE`，即使存在可能的产品细节偏差也继续下一版。
5. 未产生文件或技术门禁失败时标记 `TECHNICAL_REJECT`，修正原因后可由一个新的替补生成 Subagent 重做同一 direct 一次；第二次仍失败则跳过当前图号。技术替补不占用 `repair01`，Seedream 脚本内部的网络重试仍算同一次业务调用。

## 三版合并验收

硬失败只按当前图片的销售任务判断：

- 技术门禁未识别、到合并验收才确认的错误产品、严重产品失真或跨 Session 污染，以及未经需求与素材支持的品牌、Logo 或其他平台内容。
- `N PC` 数量错误，或者当前图片明确销售的尺寸、形状、结构、颜色、面料、定制选项不准确。
- 必需英文文案、数字、单位或关键尺寸错误、缺失、乱码、遮挡或不可读。
- 当前销售任务所必需的载体适配错误，例如尺寸图比例失真，或场景图明确展示适配却出现明显空隙、溢出或第二层原座垫。
- 无依据的认证、功效、绝对化承诺或其他平台禁止内容。

不影响当前销售任务的偏差只记为警告，并保留参加三版选优：

- 普通主图、色块图、SKU 图或场景图中偶发的轻微系带、滚边、缝线或纹理差异；结构选项图中的同类错误仍是硬失败。
- 未标注且不作为卖点的堆叠层颜色/面料顺序差异；若画面文案或销售任务声明精确顺序，则为硬失败。
- 轻微透视、比例、色差、材质表现、留白、光影、排版或构图偏差。

历史案例适用结果：JZ004 主图第 2、4 层互换记警告；SF001 色块主图多出中部系带记警告，但系带/结构选项图出现该问题时标记 `HARD_FAIL`。

## 选片与 repair01

1. 至少一版为 `ELIGIBLE` 时，综合产品还原、事实准确、可读性和构图排名，选择一版标记 `SELECTED`；警告不阻塞选片。
2. 三版均为 `HARD_FAIL` 时，只针对共同硬错误生成一次 `产品名_图类型_序号_repair01.png`。
3. `repair01` 的修复后画面出现产品时，根据构图从 manifest 产品实拍中单独选择唯一 `edit target`；不出现产品时不设置。完成技术门禁后，由另一个全新验收 Subagent 只查看该图、存在时的本次 `edit target` 和当前卖点必需素材；通过则标记 `SELECTED`。
4. `repair01` 仍有硬错误时，将图号标记 `SKIPPED`，不得继续补生；整套标记 `PARTIAL` 并列出缺失图号。

进入 FINAL 前必须存在一张 `SELECTED`，并保留三版状态、警告、硬错误、排名及 repair 记录。
