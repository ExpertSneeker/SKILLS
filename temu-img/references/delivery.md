# 交付与终验

## 制作规范

- 所有 TEMU 图片最终尺寸为 `1000*1000`。
- TEMU 不把详情页长图作为本工作流的独立输出类型。需求表中的详情、详情页、SKU、颜色图、规格图和卖点图都按副图处理，除非用户另行指定。
- 产品尺寸单位优先使用美国市场常用的 `inch`；需求表已有明确单位时按需求表执行，图片内表达必须自然、统一、易读。

**路径**

- 最终交付图片：`./output/final`
- 临时检查对比稿：`./output/temp`
- 直接生成图片、来源清单和污染隔离位置：按当前工具适配器或工具自身 skill 执行
- 最终交付不得只留在生图工具默认目录或临时目录
- 在 Windows 中文目录中处理图片或表格时，使用 Unicode 安全的绝对路径和文件 API；不要通过会丢失编码的管道或通配符把中文文件名传给脚本。出现 `????` 路径时，先修复读取方式再继续

**命名**

- 直接生成图：`产品名_图类型_序号_direct01.png`、`direct02.png`、`direct03.png`
- 唯一补生图：`产品名_图类型_序号_repair01.png`
- 最终交付图：`产品名_图类型_序号_v01.png`
- 示例：`custom_sofa_cushion_副图_01_v01.png`

## FINAL 筛选与门禁

- FINAL 只使用合并验收标记为 `SELECTED` 的 direct 或 `repair01`。
- 保存为 `1000*1000` 后，由一个全新独立验收 Subagent 执行轻量终验：确认选片来源、尺寸、当前销售任务的必需事实、平台禁止内容和整套一致性；不重复三版合并验收的全部比较过程。
- FINAL 发现硬错误时，将原 `SELECTED` 改为 `HARD_FAIL`，再把排名中的下一张 `ELIGIBLE` 改为唯一 `SELECTED`；无候选且尚未使用 `repair01` 时按生成模块补生一次，已使用或再次失败则跳过该图。
- 局部修改或准确英文文字覆盖只能保存到 `./output/temp` 作为检查对比稿。
- 最终交付不得使用本地排版或文字覆盖修补硬错误。

## FINAL 与整套终验清单

- [ ] FINAL 来自 `SELECTED` 候选并已保存到 `./output/final`
- [ ] 所有最终图片尺寸为 `1000*1000`
- [ ] FINAL 的数量、必需文案/单位、关键尺寸及当前销售的结构、颜色、面料或定制选项准确
- [ ] 整套产品身份、主要色彩、字体和视觉风格一致，且没有平台禁止内容
- [ ] 文字在移动端缩小后仍可读
- [ ] 如有局部修改或文字覆盖，检查对比稿仅保存到 `./output/temp`，FINAL 未使用本地排版或文字覆盖
- [ ] 每个图号最多使用一次 `repair01`；缺失图号已列出且整套正确标记为 `PARTIAL`
