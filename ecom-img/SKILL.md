# 电商商品图片工作流

## 启动与平台门禁（最先执行）

- 进入本 Skill 后的第一项操作是确认当前任务根目录就是当前工作目录，并记录此刻 `./DESIGN.md` 是否存在；只记录启动状态，不在完整读取通用设计规范前读取文件内容。该启动状态后续不得改变。
- 在查看产品实拍、规划图片或编写提示词前，先完整读取[平台注册与判定](references/platforms/index.md)。
- 平台只能来自用户明确指定的平台或需求表中的明确平台字段。为完成判定，可以先读取需求表文本字段，但此时不得查看表内图片或产品实拍。
- 用户要求与需求表的平台冲突、平台缺失或平台不支持时立即阻塞；不得根据文件夹名、语言、图片比例、A+、输出目录或历史任务猜测平台。
- 平台确定后先冻结平台注册表给出的唯一规范路径；按设计步骤完整读取通用设计规范后，只完整读取平台注册表中命中的唯一平台规范，不得读取、合并或借用另一个平台的规则。命中平台规范与通用设计规范冲突时，以命中平台规范为准；无冲突的规则同时执行。
- 冻结唯一平台后，同一图号的 `direct01`、`direct02`、`direct03` 必须使用同一平台规范；同一产品需要两个平台的图片时分别执行两个任务。
- 加载顺序固定为：`platforms/index.md -> design-and-prompt.md -> 当前任务根目录的 ./DESIGN.md（启动时存在才读取） -> 唯一命中平台规范 -> custom-product.md（按需） -> generation-workflow.md -> 当前工具适配器或工具 skill -> delivery.md -> 唯一命中平台规范的交付检查`。

## 开工前检查

缺一项就先报错，不要硬做或凭空补信息。

- [ ] 已按平台门禁取得唯一平台，并确认用户要求与需求表没有平台冲突
- [ ] 记录任务启动时 `./DESIGN.md` 是否存在；存在时文件可读且非空
- [ ] 有需求表
- [ ] 有产品尺寸
- [ ] `2560px拍摄图/_manifest.json` 存在，且映射中至少有一张产品实拍图
- [ ] 已按命中平台规范确认每个图号的交付类型和目标构图比例，并确认内容图型（如场景图 / 尺寸图 / 卖点图 / 颜色图 / SKU 图 / 规格图）
- [ ] 已确认采用“主 Agent 规划、同一图号所有已就绪的 direct 同轮派发、不同图号不交叉生成、每个 direct（含技术替补）由全新自定义 Subagent `product_image_creator` 调用一次生图工具并按当前工具适配器保存”
- [ ] 已按下方跨次运行缓存规则复用产品实拍查看结果，仅未命中项由自定义 Subagent `product_image_inspector` 执行 `view_image`；需求表及其他输入素材由主 Agent 查看和分类，生成结果不在查看范围内
- [ ] 已检查 VI 手册、产品图、面料图、色卡图、颜色代号图及存在时的参考图等素材可读

## 拍摄图输入门禁

- 只有 `2560px拍摄图/_manifest.json` 存在、非空时，才可继续本 Skill。
- 本 Skill 只读取映射中登记的目标文件；禁止读取、查看或传递原始拍摄图路径。
- Manifest 中的 `source_*` 字段属于原始拍摄图信息，禁止查看、回显、记录或派发；只使用 `target_path` 及目标文件所需的非来源元数据。
- 清单和缓存的 `target_path` 均相对于所在的 `2560px拍摄图` 目录，保留子目录并使用 `/`。读取、哈希计算和工具调用时解析为当前绝对路径；拒绝绝对记录路径及越界路径（含链接越界）。下文及适配器所称“登记目标文件”均按此解析。
- 本 Skill 后文的“产品实拍图”“产品实拍”“实拍输入”和“产品垫图”均指当前任务 `2560px拍摄图/_manifest.json` 中登记的目标文件，不指原始拍摄图。

## 产品实拍查看缓存（跨次运行）

- 缓存为 `./2560px拍摄图/_inspection_cache.json`，由主 Agent 保存。`files` 数组保留 inspector 返回的 `target_path`、`sha256`、`facts`、`completeness`、`viewpoint`、`occlusion`、`structure_3d`；字段含义见看图 Agent。只记录产品实拍结果，不写任务绝对路径、原图信息或生成结果。
- 每次运行按“完整相对路径＋实际文件 SHA256＋字段完整”匹配缓存，不为匹配而看图。缓存缺失或损坏视为空，单项无效只补该项；目录位置变化不影响命中。
- 全部命中时直接复用，不启动 inspector。否则将未命中项按 manifest 顺序均分为互不重叠的非空组，组数取未命中项数与当前可用子代理名额的较小值；无可用名额时等待，不另设业务并发上限。每组均以 `agent_type="product_image_inspector"`、`fork_turns="none"` 创建全新实例并行查看，只派发本组未命中项的相对路径、当前绝对路径及 SHA256 和本组 manifest 相对路径清单，不派发有效缓存；模型与推理强度沿用角色配置，不在派发参数中覆盖。
- 主 Agent 待各组结束后汇总结果，逐组核对返回路径属于本组且无重复，成功记录的 SHA256 匹配且字段完整，并检查分配项是否遗漏；无效记录与漏项列为失败项。将各组有效成功记录与有效缓存按完整相对路径合并为当前 manifest 的整体结果，不受返回顺序影响。同次运行后续图号复用，图片变化时仍只补查变化项。
- 只保留当前 manifest 的成功记录；失败或漏项单列，不沿用旧事实，补齐后再锁定完整产品基准。记录变化时由主 Agent 写入同目录临时文件后原子替换缓存；保存失败保留原文件并报告。
- 缓存仅用于产品基准查看；其他素材及生成 Agent 的当前 direct 实际输入仍按原规则查看。

## 图片输入分类

- 实际生成输入：manifest 产品实拍、颜色/面料、结构细节、插入或辅助素材；继续按实际路径显式传入当前生图工具，并在提示词中使用连续的 `Image N`。
- 产品实拍的准确色块只按当前 direct 的实际选图匹配：先完成场景、构图、版式和实拍选择，再为该 direct 已选的每张实拍匹配对应色块并一起传入；不得提前要求 manifest 全部实拍建立配对，未被该 direct 选中的实拍无需匹配或验证色块。
- 同色的多张已选实拍可以共用一张对应色块，实际输入只传一次并记录它对应的全部实拍。已选实拍找不到明确对应色块时阻塞当前 direct，不得根据实拍色差或颜色文字猜测。
- 反推专用参考图：只会出现在需求表中，指其中带产品、仅用于版式、场景或视觉叙事参考的图片；只允许主 Agent 查看、确定并反推版式、区域比例、场景、背景、道具、光线、视觉层级、展示数量、图片表达的卖点意图，以及体现卖点的场景、动作、产品状态、道具关系、对比和真实细节特写等视觉元素，禁止传给任何 Subagent 或当前生图工具。
- 反推专用参考图中的产品外观、颜色、面料、产品结构、Logo、品牌均不得提取；反推的卖点只作为视觉叙事候选，必须由需求表、用户确认或已核实产品事实支持，不符合当前产品或无事实支持的功能、结构、功效及其视觉元素不得保留。现成英文和标题/副标题信息层级仅按设计模块的文案规则提取。展示的产品数量只作为构图信息；需求表明确的 `N PC` 或售卖数量始终优先，且不得将反推数量记为商品规格。
- 反推专用参考图不是开工必选项：有则按生成模块分配给不同 direct 使用反推结果；没有则由主 Agent 独立规划三版，不得因此阻塞。

## 生图工具选择器

- 当前任务明确指定生图工具时使用指定工具；如果 `references/<工具名>.md` 存在，先完整读取该适配器，否则读取该工具自身 skill。
- `豆包`、`豆包生图`、`Seedream`、`Seedream 5.0 Pro`、`seedream5.0pro` 均指 Seedream 5.0 Pro：完整读取 [seedream.md](references/seedream.md)，并直接运行 `scripts/seedream5_pro.py`。用户明确“用豆包生成”时不得转交其他生图工具。
- 未指定生图工具时使用 `$imagegen`，并完整读取 [imagegen.md](references/imagegen.md)。
- 工具只选择一次，后续统一称“当前生图工具”。

## 设计步骤

严格按以下顺序执行，缺一不可。

1. 规划图片与编写提示词前的步骤
    - 完整读取 [design-and-prompt.md](references/design-and-prompt.md)。
    - 保持当前任务根目录为工作目录，复用入口已记录的启动状态；若启动时 `./DESIGN.md` 存在，随后完整读取并按设计模块校验、冻结其中的视觉语言，若不存在则按设计模块确定基准，不得在任务中途改用后来出现的文件重定已冻结风格。
    - 随后完整读取平台门禁唯一命中的平台规范；不得读取另一平台规范。
    - 若用户或需求表明确支持定制，或者尺寸为连续可选区间时，完整读取 [custom-product.md](references/custom-product.md)。
    - 产品实拍图只按拍摄图输入门禁处理；其他不可读取的 JPG/JPEG/PNG 参考图片必须先转码或用其他工具打开。
2. 确认 `2560px拍摄图/_manifest.json` 映射非空后，按上方“产品实拍查看缓存（跨次运行）”读取、校验并仅补看未命中项；全部命中时不派发 inspector。主 Agent 根据当前 manifest 的完整合并结果锁定产品身份、颜色、纹理、结构、比例和禁止偏离项，后续图号复用该结果。
3. 主 Agent 读取 `.xlsx/.xls` 需求表中的需求、参考图、文案与语言字段、尺寸、交付类型、内容图型、颜色/SKU 等信息，识别 WPS `DISPIMG` 单元格图片并亲自执行 `view_image`；结合已锁定的产品基准，确定需求表中哪些图片是反推专用参考图。需求表以外的颜色/面料、结构细节、插入或辅助图片也由主 Agent 查看并确定角色。
4. 从需求表取得并理解产品尺寸，按人物、家具、手持、宠物、儿童或使用场景校验比例，并按设计模块处理需求表与命中平台规范的优先级；
5. 按设计模块分别处理产品颜色展示和色块素材缺失，不得凭空编造颜色。
6. 主 Agent 确认第 3 步的输入素材查看与分类记录完整，复用已完成结果，只补查新增、变化或遗漏的输入素材；排除生成结果。
7. 组织主 Agent 与单版生成 Subagent、准备输入或开始生成前，完整读取 [generation-workflow.md](references/generation-workflow.md)。
8. 已确定的反推专用参考图存在时先形成反推结果并按 direct 分配，不存在时自行规划三版；确定各 direct 的场景、构图和卖点视觉表达后，为每个出现产品的 direct 从 manifest 产品实拍中分别选择唯一 `edit target`，再确定确实需要的其他实拍。三个 direct 可以使用同一 `edit target`，也可以分别使用不同实拍，不得强制统一。只在每个 direct 的实拍选定后，为该 direct 已选的每张实拍匹配准确色块；同色色块去重后，与实拍及其他必需素材一起编排为连续的 `Image N`。找不到明确对应色块时阻塞该 direct；要求改色但缺少目标色块时阻塞该图号。首次生图前先冻结平台、交付类型、目标构图比例、文案语言、单位和整套视觉语言基准，再按设计模块的提示词编写步骤与格式完整预写 `direct01`、`direct02`、`direct03` 三版提示词并完成生图前检查。派发生成 Subagent 前，提示词只能保留命中平台的最终值，不得残留平台选择说明、候选比例或另一平台的术语；调用前按选择器读取对应适配器或工具自身 skill，再使用当前生图工具进行整图图生图。
9. 每张图片生成 `direct01`、`direct02`、`direct03` 三个版本，三版提示词必须有明确调整。完成预检后，按生成模块的“生成、保存与技术确认”执行派发、文件检查、终态记录和图号推进，并按工具适配器保存到直接生成目录；只作非视觉文件确认，不查看、比较或挑选生成结果。
10. 当前工具或 Session 中断、超时或未稳定进入下一次生成时，不得标记完成；先核对已有文件及调用记录，按生成模块和当前适配器区分恢复保存、允许的技术替补与待核实暂停，不仅凭缺失图号重新生成。
11. 报告完成前完整读取 [delivery.md](references/delivery.md)，按交付模块核对三版直接生成文件、记录、路径和命名，再执行已命中平台文件中的“交付检查”；不得读取另一平台文件，不得查看生成图片。交付阶段不额外复制、另建 FINAL、改名、缩放或本地修图；ImageGen 按适配器执行的首次串行保存仍是必需步骤。
12. 所有计划 direct 均已标记 `SAVED` 或按生成模块记录最终 `TECHNICAL_REJECT`，且第 11 步的交付检查完成后，按交付模块处理 `./DESIGN.md`；有待核实暂停项时不收尾。启动时已存在则保持不变；启动时不存在且结束时仍不存在才创建，结束时已有文件则不得覆盖。
