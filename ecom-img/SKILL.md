# 电商商品图片工作流

## 平台门禁（最先执行）

- 在查看产品实拍、规划图片或编写提示词前，先完整读取[平台注册与判定](references/platforms/index.md)。
- 平台只能来自用户明确指定的平台或需求表中的明确平台字段。为完成判定，可以先读取需求表文本字段，但此时不得查看表内图片或产品实拍。
- 用户要求与需求表的平台冲突、平台缺失或平台不支持时立即阻塞；不得根据文件夹名、语言、图片比例、A+、输出目录或历史任务猜测平台。
- 平台确定后先冻结平台注册表给出的唯一规范路径；按设计步骤完整读取通用设计规范后，只完整读取 [Amazon 规范](references/platforms/amazon.md) 或 [TEMU 规范](references/platforms/temu.md) 中命中的一个，不得读取、合并或借用另一个平台的规则。
- 冻结唯一平台后，同一图号的 `direct01`、`direct02`、`direct03` 必须使用同一平台规范；同一产品需要两个平台的图片时分别执行两个任务。
- 加载顺序固定为：`platforms/index.md -> design-and-prompt.md -> 唯一命中平台规范 -> custom-product.md（按需） -> generation-workflow.md -> 当前工具适配器或工具 skill -> delivery.md -> 唯一命中平台规范的交付检查`。

## 开工前检查

缺一项就先报错，不要硬做或凭空补信息。

- [ ] 已按平台门禁取得唯一平台，并确认用户要求与需求表没有平台冲突
- [ ] 有需求表
- [ ] 有产品尺寸
- [ ] `2560px拍摄图/_manifest.json` 存在，且映射中至少有一张产品实拍图
- [ ] 已按命中平台规范确认每个图号的交付类型和目标构图比例，并确认内容图型（如场景图 / 尺寸图 / 卖点图 / 颜色图 / SKU 图 / 规格图）
- [ ] 已确认采用“主 Agent 规划、所有图号全局串行生图、每个 direct 由全新单版生成 Subagent 调用一次生图工具并直接保存”
- [ ] 已确认 manifest 产品实拍查看显式调用自定义 Subagent `product_image_inspector`，需求表及其他图片由主 Agent 查看和分类
- [ ] 已确认 `2560px拍摄图/_manifest.json` 登记的实拍图由 `product_image_inspector` 执行 `view_image`，需求表及其他图片由主 Agent 执行 `view_image`
- [ ] 已检查 VI 手册、产品图、面料图、色卡图、颜色代号图及存在时的参考图等素材可读

## 拍摄图输入门禁

- 只有 `2560px拍摄图/_manifest.json` 存在、非空时，才可继续本 Skill。
- 本 Skill 只读取映射中登记的目标文件；禁止读取、查看或传递原始拍摄图路径。
- Manifest 中的 `source_*` 字段属于原始拍摄图信息，禁止查看、回显、记录或派发；只使用 `target_path` 及目标文件所需的非来源元数据。
- 本 Skill 后文的“产品实拍图”“产品实拍”“实拍输入”和“产品垫图”均指当前任务 `2560px拍摄图/_manifest.json` 中登记的目标文件，不指原始拍摄图。

## 图片输入分类

- 实际生成输入：manifest 产品实拍、颜色/面料、结构细节、插入或辅助素材；继续按实际路径显式传入当前生图工具，并在提示词中使用连续的 `Image N`。
- 产品实拍的准确色块只按当前 direct 的实际选图匹配：先完成场景、构图、版式和实拍选择，再为该 direct 已选的每张实拍匹配对应色块并一起传入；不得提前要求 manifest 全部实拍建立配对，未被该 direct 选中的实拍无需匹配或验证色块。
- 同色的多张已选实拍可以共用一张对应色块，实际输入只传一次并记录它对应的全部实拍。已选实拍找不到明确对应色块时阻塞当前 direct，不得根据实拍色差或颜色文字猜测。
- 反推专用参考图：只会出现在需求表中，指其中带产品、仅用于版式、场景或视觉叙事参考的图片；只允许主 Agent 查看、确定并反推版式、区域比例、场景、背景、道具、光线、视觉层级、展示数量、图片表达的卖点意图，以及体现卖点的场景、动作、产品状态、道具关系、对比和真实细节特写等视觉元素，禁止传给任何 Subagent 或当前生图工具。
- 反推专用参考图中的产品外观、颜色、面料、产品结构、Logo、品牌均不得提取；反推的卖点只作为视觉叙事候选，必须由需求表、用户确认或已核实产品事实支持，不符合当前产品或无事实支持的功能、结构、功效及其视觉元素不得保留。现成英文和标题/副标题信息层级仅按设计模块的文案规则提取。展示的产品数量只作为构图信息；需求表明确的 `N PC` 或售卖数量始终优先，且不得将反推数量记为商品规格。
- 反推专用参考图不是开工必选项：有则按生成模块分配给不同 direct 使用反推结果；没有则由主 Agent 独立规划三版，不得因此阻塞。

## 生图工具选择器

- 当前任务明确指定生图工具时使用指定工具；如果 `references/<工具名>.md` 存在，先完整读取该适配器，否则读取该工具自身 skill。
- `豆包`、`豆包生图`、`Seedream`、`Seedream 5.0 Pro`、`seedream5.0pro` 均指 Seedream 5.0 Pro：完整读取 [seedream.md](references/seedream.md)，并直接运行 `scripts/seedream5_pro.py`。用户明确“用豆包生成”时不得转交其他生图工具。
- 未指定生图工具时使用 `$imagegen`，并完整读取 [imagegen.md](references/imagegen.md)。
- 工具只选择一次，后续统一称“当前生图工具”。

## 设计步骤

严格按以下顺序执行，缺一不可。

1. 规划图片与编写提示词前的步骤
    - 完整读取 [design-and-prompt.md](references/design-and-prompt.md)。
    - 随后完整读取平台门禁唯一命中的平台规范；不得读取另一平台规范。
    - 若用户或需求表明确支持定制，或者尺寸为连续可选区间时，完整读取 [custom-product.md](references/custom-product.md)。
    - 产品实拍图只按拍摄图输入门禁处理；其他不可读取的 JPG/JPEG/PNG 参考图片必须先转码或用其他工具打开。
2. 确认 `2560px拍摄图/_manifest.json` 映射非空后，显式调用一个全新的 `product_image_inspector` 查看映射中的全部产品实拍目标文件；主 Agent 根据返回结果锁定产品身份、颜色、纹理、结构、比例和禁止偏离项。
3. 主 Agent 读取 `.xlsx/.xls` 需求表中的需求、参考图、文案与语言字段、尺寸、交付类型、内容图型、颜色/SKU 等信息，识别 WPS `DISPIMG` 单元格图片并亲自执行 `view_image`；结合已锁定的产品基准，确定需求表中哪些图片是反推专用参考图。需求表以外的颜色/面料、结构细节、插入或辅助图片也由主 Agent 查看并确定角色。
4. 从需求表取得并理解产品尺寸，按人物、家具、手持、宠物、儿童或使用场景校验比例，并按设计模块处理需求表与命中平台规范的优先级；
5. 按设计模块分别处理产品颜色展示和色块素材缺失，不得凭空编造颜色。
6. 主 Agent 完成需求表图片和除了`2560px拍摄图`之外的其他图片的查看与分类。
7. 组织主 Agent 与单版生成 Subagent、准备输入或开始生成前，完整读取 [generation-workflow.md](references/generation-workflow.md)。
8. 已确定的反推专用参考图存在时先形成反推结果并按 direct 分配，不存在时自行规划三版；确定各 direct 的场景、构图和卖点视觉表达后，为每个出现产品的 direct 从 manifest 产品实拍中分别选择唯一 `edit target`，再确定确实需要的其他实拍。三个 direct 可以使用同一 `edit target`，也可以分别使用不同实拍，不得强制统一。只在每个 direct 的实拍选定后，为该 direct 已选的每张实拍匹配准确色块；同色色块去重后，与实拍及其他必需素材一起编排为连续的 `Image N`。找不到明确对应色块时阻塞该 direct；要求改色但缺少目标色块时阻塞该图号。首次生图前先冻结平台、交付类型、目标构图比例、文案语言和单位，再按设计模块的提示词编写步骤与格式完整预写 `direct01`、`direct02`、`direct03` 三版提示词并完成生图前检查。派发生成 Subagent 前，提示词只能保留命中平台的最终值，不得残留平台选择说明、候选比例或另一平台的术语；调用前按选择器读取对应适配器或工具自身 skill，再使用当前生图工具进行整图图生图。
9. 每张图片生成 `direct01`、`direct02`、`direct03` 三个版本；三版提示词必须有明确调整，并分别直接保存到当前工具规定的直接生成路径。所有图号共用一个生图槽，同一时间只允许一个单版生成 Subagent 调用生图工具。
    - 每次生成前按当前工具适配器或自身 skill 建立调用记录，每次只接受可唯一归属本次调用的一张源图。
    - 单版生成 Subagent 返回结果后，主 Agent 和其他 Agent 均不得查看生成图片；主 Agent 只核对返回路径、文件可读性、比例尺寸、哈希和调用记录。
    - 文件完整且来源唯一时标记 `SAVED` 并继续下一版；不检查产品细节、颜色、文案或构图，不比较三版，不选片，也不因图片内容重新生成。
    - 未产出文件、文件损坏、来源无法唯一确认或比例尺寸无法读取时标记 `TECHNICAL_REJECT`；修正技术原因后可由一个全新替补生成 Subagent 重试同一 direct 一次，第二次仍失败则记录缺失并继续其他图号。
10. 当前工具或 Session 中断、超时或未稳定进入下一次生成时，不得标记完成；核对直接生成目录的文件数量、大小和时间戳，从缺失图型及序号继续补齐。
11. 报告完成前完整读取 [delivery.md](references/delivery.md)，按交付模块核对三版直接生成文件、记录、路径和命名，再执行已命中平台文件中的“交付检查”；不得读取另一平台文件，不得查看生成图片，不另建 FINAL，不复制、改名、缩放或本地修图。
