# 电商商品图片

## 任务路由

先确认任务根目录与本次交付目标。仅规划、生成、恢复是任务范围，不由是否处于 Plan mode 决定。

- **仅规划／编写提示词**：用已有且获准读取的信息交付方案或提示词草案，明确待补事实和受影响图号。不调用生图、不自动初始化、不创建或修改 DESIGN、manifest、缓存、调用记录等生产状态文件。缺少 manifest 时仍可依据需求文字作有限规划，但不得读取原图或以未登记图片替代产品实拍；不完整草案不得作为可执行的冻结任务包。
- **生成**：在任务根目录工作，记录进入生成模式时 `./DESIGN.md` 是否存在。完成下述适用门禁、设计与冻结后，按生成模块执行所有计划图号；不在第一版结束时自动停下等待确认。
- **恢复**：先读已有调用记录和当前工具适配器，只恢复允许的保存、下载或技术替补。文件缺失不等于可以重生；仅恢复保存时不重做设计、不重建 DESIGN、不重跑素材检查。若记录允许新的技术替补，仍须满足生成门禁并使用对应冻结任务包。

## 不可遗漏的边界

- 产品实拍仅使用 `2560px拍摄图/_manifest.json` 登记目标；原图及 `source_*` 不进入 Agent、输出或生图输入，拒绝路径越界及链接逃逸。缺 manifest 不自动调用初始化 Skill，须由用户明确调用 `$init-2560px-images`。
- 产品真实性、真实尺寸与数量、最终颜色依据、唯一合格底图及定制例外按对应模块执行。反推参考图及其内部来源记录不传给子代理或生成工具。
- 用户明确覆盖旧平台或视觉字段时只更新该字段的有效任务基准，保留其他字段；不覆盖平台强制要求、原图边界或未解决的品牌硬约束，不擅自覆写既有 DESIGN。
- 生成仍为每图号三个独立 direct，主 Agent 规划，独立 `product_image_creator` 执行冻结合同；原有角色配置、并发和调用上限不变。
- 不查看生成结果、不挑选 FINAL、不因内容返修或生成后修图。仍确认文件、唯一来源和哈希；结果未知不重新 POST，下载恢复不重新生成。

## 生成门禁与工具

生成前须有明确且受支持的平台、需求表、产品尺寸、非空有效 manifest；各图号的交付类型、内容图型、构图比例、语言和单位按需求及平台冻结。完成产品基准、实际素材分类、适用定制规则及视觉基准；仅检查当前任务使用的素材。参考图可缺省，最终颜色依据不得缺省。SKU 未明确要求逐色交付时按设计模块采用单色默认；明确要求时按指定颜色及规格制作，不扩展未要求的组合。交付范围有歧义或必要颜色素材缺失时，只暂停受影响项。

首次调用前完整预写当前图号 direct01、direct02、direct03；各任务包均按生成模块完成一次预检，未通过项不得派发。只对新增、变化或失败项重检。既有 DESIGN 不覆盖；缺失时仅生成模式按视觉模块建立。

用户指定工具时使用指定工具，读取现有对应适配器，否则读取工具自身 Skill；未指定时使用 `$imagegen` 与 [ImageGen 适配器](references/imagegen.md)。`豆包`、`豆包生图`、`Seedream`、`Seedream 5.0 Pro`、`seedream5.0pro` 均使用 [Seedream 适配器](references/seedream.md)及 `scripts/seedream5_pro.py`，不得转交其他生图工具。任务内不自行换工具。

仅规划以方案和待补项交付；生成／恢复按生成模块区分完整交付、部分交付、最终技术失败与结果待核实，不将“处理完”说成“全部成功”。
