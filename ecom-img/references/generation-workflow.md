# 通用生成流程

本文件是三版生成、直接保存和技术重试上限的唯一规则源；工具适配器只补充调用与恢复差异。

## Agent 职责

**主 Agent**

- 锁定每个图号的销售任务、产品基准和必需事实；形成并分配反推结果、确定各版场景、构图与卖点视觉表达后，再为每个出现产品的 direct 分别选择唯一 `edit target` 和确实需要的其他实拍。实拍选定后才逐张匹配准确色块并确定其他输入路径；同色色块去重后与实拍一起传入。三个 direct 可以复用同一底图，也可以使用不同底图。
- 派发当前图号前，分别冻结每个 direct 的提示词、输入路径及顺序、唯一输出路径和当前工具硬性调用合同；任一任务包未完成预检时不得派发该 direct。
- 显式调用 `product_image_inspector` 查看 manifest 产品实拍并根据返回结果锁定产品基准；需求表及其他图片必须由主 Agent 查看和分类。
- 逐版判断人物、载体、尺寸、坐垫厚度等条件规则是否适用，并确认对应约束已经实际写入冻结提示词，不能只保留在技能文档、内部记录或派发说明中。出现 bench、chair、window seat、sofa 等承载关系时，提示词必须明确产品沿长宽完全覆盖载体可用承载面、四边分别对齐、四周无可见空余承载面且不得改变产品比例；缺少任一项时阻塞该 direct。
- 将需求表中带产品的版式、场景或视觉叙事参考图仅作为反推专用参考图，完成反推和内部来源记录；不得把该图路径、名称、图片编号或对该图的引用写入生成提示词或派发给生成 Subagent。
- 只负责派发、非视觉文件完整性确认、记录和推进流程，不直接调用生图工具。
- 同一图号所有已就绪的 direct 同轮派发，不设置并发上限或生图槽计数；不同图号不交叉生成。当前图号所有 direct 完成文件检查并进入终态后，立即开始下一图号。
- 生图是否结束只依据 direct 的文件检查与终态记录，不依据 Agent 列表、空闲槽数量、并发计数或已返回但尚未关闭的 Subagent 是否仍显示存在。
- 每个图号只执行三版生成；不得查看、比较或挑选生成结果，也不得因图片内容补生。

**产品实拍查看 Subagent (`product_image_inspector`)**

- 使用一个全新的 `product_image_inspector`，只查看 `2560px拍摄图/_manifest.json` 登记的全部目标文件，逐张返回绝对路径和产品可见事实；主 Agent 据此锁定产品身份、颜色、纹理、结构、比例和禁止偏离项。
- 产品基准锁定后，主 Agent 亲自查看需求表中的全部图片和需求表以外的颜色/面料、结构细节、插入或辅助图片等，记录路径、来源位置、可见事实、分类、理由和适用图号，并冻结分类。

**生成 Subagent**

- 每个 direct 使用一个全新 Subagent；只接收当前冻结提示词、产品基准、该 direct 自己的唯一 `edit target`（目标画面不出现产品时不设置）、其他已选实拍、实拍与对应色块的映射、其他实际生成输入的准确路径、唯一目标文件名和当前工具适配器的硬性调用合同，只调用一次当前生图工具。
- 选择 ImageGen 时，硬性调用合同必须逐项列出按 `Image N` 顺序冻结的 `referenced_image_paths`，并明确禁止 `num_last_images_to_include`；路径、顺序或参数合同缺失时不得调用。生成 Subagent 不自行补写、删减或改写冻结提示词中的条件约束。
- 在自己的上下文中重新查看全部实际输入，按当前顺序记录角色并完成来源登记，再调用当前生图工具。
- 按当前工具适配器处理唯一结果：由生成 Subagent 直接保存到规定路径，或在适配器要求主 Agent 串行保存时返回明确源路径和完整来源记录；返回后退出，不得查看生成结果。
- 同一图号的生成 Subagent 彼此独立，不等待其他 direct 的生成、检查或终态，也不得读取、引用或继承其他 direct 的上下文。

## view_image 与图片角色

- 所有参与生图的输入图片必须在生成前执行 `view_image`；产品实拍只允许使用 `2560px拍摄图/_manifest.json` 登记的目标文件，禁止查看或传递原始拍摄图。生成结果不得执行 `view_image`。
- 每个生成 Subagent 只对当前 direct 的实际生成输入连续编号，不沿用其他 direct 或 Session 的编号。目标画面出现产品时必须且只能有一个 `edit target`；其他角色为 primary product identity、source color authority、target color authority、detail/structure、insert/supporting asset。不同 direct 的 `edit target` 路径互不绑定。
- 先按场景、构图和版式选择当前 direct 的实拍，再只为这些已选实拍匹配准确色块；未选实拍无需匹配或验证色块。每张已选实拍必须有明确对应色块，同色的多张实拍可共用一张色块并只传一次，但必须记录该色块对应的全部实拍。
- 已选实拍缺少明确对应色块时阻塞当前 direct；要求改色但缺少目标色块时阻塞当前图号。不得按实拍观感、近似色或颜色文字猜测，也不得先调用生图工具再补配对。
- 输入格式: `Image N = 图片身份`
- 格式举例: `Image 1 = edit target`
- 提示词中的 `Image N`、适配器输入顺序和实际文件顺序必须一致。

## 反推专用参考图

- 反推专用参考图是可选项；没有时不得阻塞，主 Agent 根据当前图号的销售任务独立规划三个 direct 的场景、构图和卖点视觉表达。
- 反推专用参考图只会出现在需求表中。只有主 Agent 在产品基准锁定后亲自查看并冻结分类，图片才确定为反推专用参考图；不得将其列入实际生成输入、连续 `Image N` 或适配器参数。
- 需求表中带当前产品或竞品产品、用途仅为版式、场景或视觉叙事借鉴，且不承担当前产品身份、颜色/面料、结构细节或插入素材角色的图片，可分类为反推专用参考图；需求表以外的图片不得分类为反推专用参考图，无法确定角色时分类为不使用。
- 只反推版式结构、区域比例、场景、背景、道具、光线、视觉层级、白底或人物是否出现、展示数量、图片表达的卖点意图，以及体现卖点的场景、动作、产品状态、道具关系、对比和真实细节特写等视觉元素；反推的卖点只作为视觉叙事候选，不符合当前产品的功能、结构、功效及其视觉元素不得保留。不得提取竞品产品外观、颜色、面料、结构、Logo、品牌；现成英文和标题/副标题信息层级仅按设计模块的文案规则提取。
- 锁定产品真实性基准后、确定各 direct 的其他实际生成输入前，将允许提取的内容改写为独立、具体的反推结果。生成提示词不得提及反推专用参考图、其路径、名称或图片编号，也不得出现“参考/忽略该图产品”等指令。
- 主 Agent 在提示词之外保留 `【内部参考反推记录】`，逐张记录绝对路径、分析角色、反推结果中的版式/场景/展示数量、卖点意图及其视觉元素，并记录支持或排除该卖点的需求表、用户确认或已核实产品事实来源，以及产品数量、尺寸、形状、结构、颜色、面料和文案等商品规格的真实来源。该记录不得写入提示词文件或派发给生成 Subagent 和生图工具。
- 同一图号有多张反推专用参考图时，优先让不同 direct 使用不同参考图的反推结果，每个 direct 最多分配一张。恰有三张时一版一张；多于三张时由主 Agent 按销售任务匹配度和三版差异化价值选择三张；少于三张时可重复使用参考图。分配结果写入内部记录，数量不匹配不得阻塞。
- 反推的展示数量只用于构图；需求表明确的 `N PC` 或售卖数量始终优先，且不得将反推数量登记为商品规格。

## 产品与提示词基准

- 首次生图前锁定产品身份、纹理、光泽、结构、比例、售卖数量、真实尺寸和载体适配；定制产品同时锁定形状能力及结构选项依据。每个 direct 的实拍选定后，另行冻结实拍与对应色块的映射；未改色时由对应色块决定产品颜色，改色时由目标色块决定最终颜色。
- 产品身份和商品规格只依据 manifest 产品实拍、需求表、用户确认及已声明的实际生成输入；反推专用参考图的反推结果只控制场景、版式、卖点的视觉叙事和文案信息层级，不得成为商品规格或未经核实卖点的依据。
- 三版共同的产品身份、商品事实、当前图号的销售任务、核心卖点和目标构图比例不变，只调整各自声明的场景、视觉叙事或版式。每个 direct 的 `edit target` 属于该版实际输入，不属于三版共同基准；底图可以相同或不同，但不得因此改变产品身份、商品事实、销售任务、核心卖点或目标构图比例。

## 生成、保存与技术确认

1. 派发当前图号前，逐个确认每个 direct 已完成“规划场景、构图和版式 -> 选择实拍 -> 为每张已选实拍匹配对应色块 -> 去重并连续编号”的顺序，再按适配器完成输入数量、路径和格式预检，并冻结各自的任务包。已选实拍与对应色块必须一起传入；配对、目标色块或预检缺失时阻塞该 direct，不调用工具。
2. 当前图号所有已就绪的 direct 分别由全新生成 Subagent 在同一轮派发，每个 Subagent 只处理一个 direct、只接受一张可唯一归属的结果；不同图号不交叉生成。
3. 生成 Subagent 按当前工具适配器保存唯一结果，或在适配器要求主 Agent 串行保存时返回明确源路径和完整来源记录；生成 Subagent、主 Agent 和其他 Agent 均不得查看生成图片。
4. 每个生成 Subagent 返回后，主 Agent 只执行下列非视觉文件确认：
   - 文件已保存到规定路径，可正常读取并取得比例尺寸；不以实际宽高比是否匹配提示词中的目标构图比例作为技术验收条件。
   - 源路径、源/目标哈希、比例尺寸、提示词编号和来源记录完整且唯一。
   - 返回结果与当前任务、图号、direct、调用开始时间和目标文件名的来源记录一致，不依赖图片内容判断归属。
5. 通过文件确认的结果标记 `SAVED`，不检查产品细节、颜色、文案或构图，不比较三版，也不因图片内容重新生成。
6. 文件检查与终态记录完成后，运行环境提供 `close_agent` 时，主 Agent 立即关闭对应生成 Subagent；运行环境没有关闭接口时，以 Subagent 的 `completed` 或 `errored` 为生命周期终态，不额外等待。关闭动作属于资源清理，不改变 direct 的终态判断。
7. 未产出文件、文件损坏、来源无法唯一确认或比例尺寸无法读取时标记 `TECHNICAL_REJECT`；主 Agent 先按第 6 步关闭原 Subagent，再在当前图号的初始批次结束后，由一个新的替补生成 Subagent 重做同一 direct 一次。其他已标记 `SAVED` 的 direct 不重复生成；第二次仍失败则记录最终 `TECHNICAL_REJECT`。Seedream 脚本内部的网络重试仍算同一次业务调用。
8. 当前图号所有 direct 均已完成检查并进入 `SAVED` 或最终 `TECHNICAL_REJECT` 后，立即同轮派发下一图号所有已就绪的 direct；不得等待 Agent 列表清空。
