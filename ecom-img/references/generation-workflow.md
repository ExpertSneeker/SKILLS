# 生成、恢复与技术终态

本文件仅适用于已授权的生成或恢复，不将规划草案升级为生产任务。三版生成、直接保存和业务技术替补上限以本文件为准；工具适配器可进一步收紧。每个 direct 最多一次技术替补，不绕过累计调用限制。

## 职责与容量

- 主 Agent 按 [输入合同](inputs.md)、[设计模块](design-and-prompt.md) 与 [视觉基准](visual-language.md) 取得完整事实和素材，冻结当前图号三版任务包；生成阶段仅派发、确认文件、记录与推进，不直接调用生图工具。
- 产品 inspector 仅查看本组未命中项，保持只读。缓存已全部有效时不派发；合并、漏项检查与缓存写入按输入合同由主 Agent 执行。
- 同一图号所有已就绪的 direct 按运行环境可用容量同轮派发，容量不足时待释放后继续派发该图号，不额外设置业务并发上限或生图槽计数；不同图号不交叉生成。当前图号所有 direct 完成文件检查并进入终态后，立即开始下一图号。
- 生图是否结束只依据 direct 的文件检查与终态记录，不依据 Agent 列表、空闲槽数量、并发计数或已返回但尚未关闭的 Subagent 是否仍显示存在。
- 每个图号只执行三版生成；不得查看、比较或挑选生成结果，也不得因图片内容补生。

## 生成子代理合同

- 本技能及工具适配器中的“生成 Subagent”“单版生成 Subagent”和“替补生成 Subagent”均指 `product_image_creator`。首次生成与技术替补均显式使用 `agent_type="product_image_creator"`、`fork_turns="none"` 创建全新实例，并通过派发消息完整提供当前 direct 的冻结任务包；模型与推理强度由该角色的独立配置固定，不在派发参数中覆盖。

- 每个 direct 使用一个全新 Subagent；只接收当前冻结提示词、产品基准、该 direct 自己的唯一 `edit target`（目标画面不出现产品时不设置）、其他已选实拍、各色块与成图产品最终颜色及展示用途的映射、其他实际生成输入的准确路径、唯一目标文件名和当前工具适配器的硬性调用合同，只调用一次当前生图工具。
- 选择 ImageGen 时，硬性调用合同必须逐项列出按 `Image N` 顺序冻结的 `referenced_image_paths`，并明确禁止 `num_last_images_to_include`；路径、顺序或参数合同缺失时不得调用。生成 Subagent 不自行补写、删减或改写冻结提示词中的条件约束。
- 在自己的上下文中重新查看全部实际输入，按当前顺序记录角色并完成来源登记，再调用当前生图工具。查看结果只记入执行记录，不改写冻结正文，不把内部记录或整个任务包作为 prompt；实际输入路径和参数严格按冻结调用合同传递。
- 按当前工具适配器处理唯一结果：由生成 Subagent 直接保存到规定路径，或在适配器要求主 Agent 串行保存时返回明确源路径和完整来源记录；返回后退出，不得查看生成结果。
- 同一图号的生成 Subagent 彼此独立，不等待其他 direct 的生成、检查或终态，也不得读取、引用或继承其他 direct 的上下文。

## 生成前预检

当前图号首次派发前，完成三版提示词、各自连续 Image N 输入顺序、唯一输出路径、提示词编号和当前工具硬性调用合同；内部记录与工具 prompt 分离。每版单独核对以下条件，已检查且未变化的结果复用；新增、变化或失败项只复检受影响部分。

- 根入口生成门禁已满足；产品基准、销售任务、平台、交付类型、比例、语言、单位、真实尺寸、数量、定制能力、目标颜色/面料、完整文案及视觉基准一致。每版独立满足全部明确要求，不把同画面需求拆到不同 direct。
- 已按场景构图选合格实拍，再按最终颜色及展示需求选色块、去重和编号；具体资格与缺失处理按输入合同。每版唯一 edit target、实际输入角色、颜色对应关系完整，工具输入数量、路径、格式符合适配器；无产品画面仅按已有允许分支处理。
- 适用的 [产品与场景规则](product-rules.md) 及定制例外已完整进入提示词相应字段，同一约束表达一次。内部记录保留“适用条件规则 → 字段与对应原句”，多条可映射同一句。缺失时先修正并复检，不跳图或减少交付；记录不传给生图工具。
- 检查正文只含画面指令与实际输入编号、角色和用途，不含路径、查看记录、来源追踪、调用参数或未传入图片引用；核对 `Image N` 与冻结输入顺序一致。
- 检查产品保持项与当前方案允许的变化不冲突；场景置入不得用“其他一切不变”误锁原照片背景、人物或光线。多场景画面逐区核对产品、准确件数及色块映射，每个 direct 独立满足全部场景要求。
- 有文案时逐条核对引号内的冻结文字、层级、位置与出现次数，确认没有让工具补写的内容，文字样式与整套基准一致；无文案时删除文案及字体字段并按平台要求明确无文字。检查具体光线、人物动作与接触关系已替代空泛描述，且没有新增无依据的产品属性或功效。
- 正文不得含平台选择过程、另一平台术语或候选比例；不得使用冗长负面提示词或 `generous breathing room`、`generous spacing`、`clean empty background` 等主动制造空白的泛化表述。

只有预检通过的 direct 才可派发；有限规划草案不得标成已冻结。SKU 按设计模块确定单色默认或明确的逐色交付范围；核对图号覆盖全部已要求的颜色及规格组合，不遗漏、不扩展。范围有歧义或必要颜色素材缺失时，只暂停受影响项。

## 生成、保存与技术确认

1. 当前图号所有已就绪的 direct 按上文运行环境容量规则分别由全新生成 Subagent 同轮派发，每个 Subagent 只处理一个 direct、只接受一张可唯一归属的结果；不同图号不交叉生成。
2. 生成 Subagent 按当前工具适配器保存唯一结果，或在适配器要求主 Agent 串行保存时返回明确源路径和完整来源记录；生成 Subagent、主 Agent 和其他 Agent 均不得查看生成图片。
3. 每个生成 Subagent 返回后，主 Agent 只执行下列非视觉文件确认：
   - 文件已保存到规定路径，可正常读取并取得比例尺寸；不以实际宽高比是否匹配提示词中的目标构图比例作为技术验收条件。
   - 源路径、源/目标哈希、比例尺寸、提示词编号和来源记录完整且唯一。
   - 返回结果与当前任务、图号、direct、调用开始时间和目标文件名的来源记录一致，不依赖图片内容判断归属。
4. 通过文件确认的结果标记 `SAVED`，不检查产品细节、颜色、文案或构图，不比较三版，也不因图片内容重新生成。
5. 文件检查与终态记录完成后，运行环境提供 `close_agent` 时，主 Agent 立即关闭对应生成 Subagent；运行环境没有关闭接口时，以 Subagent 的 `completed` 或 `errored` 为生命周期终态，不额外等待。关闭动作属于资源清理，不改变 direct 的终态判断。
6. 文件缺失、损坏、来源无法唯一确认或尺寸无法读取时，先按当前适配器及调用记录区分结果未知、仅需恢复保存和明确技术失败。Seedream 的 `unresolved` 或中断后遗留且结果未明的 `calling` 保持待核实，不转为最终 `TECHNICAL_REJECT`；暂停当前图号的新派发，已运行的其他 direct 可完成保存，但不得派发下一图号或标记整套完成；保留提示词编写前已读取或创建的 `DESIGN.md`。
   - 仅保存或下载失败时先按适配器恢复，不重新生成。
   - 明确技术失败时标记 `TECHNICAL_REJECT`，按第 5 步处理原 Subagent 生命周期；当前图号初始批次结束后，仅在适配器和记录允许时，由全新替补重做同一 direct 一次。替补仍失败或工具已不允许重试时记录最终 `TECHNICAL_REJECT`；已标记 `SAVED` 的 direct 不重做。Seedream 内部网络重试属于同一次业务调用，但仍计入其累计 POST 上限。
7. 当前图号所有 direct 均已完成检查并进入 `SAVED` 或最终 `TECHNICAL_REJECT` 后，立即同轮派发下一图号所有已就绪的 direct；不得等待 Agent 列表清空。

## 状态与结束条件

- **完整交付**：所有计划 direct 均为 SAVED，且交付检查完成。
- **部分交付**：已保存部分 direct，其余为最终 TECHNICAL_REJECT；报告成功数、计划数、缺失路径和技术原因，不能称全部成功。
- **最终技术失败**：技术替补耗尽或适配器已不允许继续；该 direct 没有交付成功。若整套无 SAVED，报告整套技术失败；失败项不是待无限重试的任务。
- **结果待核实**：有 unresolved 或中断后结果未明的 calling；保留记录，不重新 POST、不标成最终失败或整套完成。已运行 direct 可以保存，暂停该图号新派发及下一图号。可报告阻塞状态，但不得把结束一轮回复等同于任务完成。
- **条件待补／业务待确认**：未达到生成门禁、颜色及规格交付范围有歧义等项不得调用，不伪装成 TECHNICAL_REJECT。按现有图号调度边界继续不依赖该项的准备工作；当前图号未到终态时不跨图号生成。

只恢复保存或下载时复用对应记录与冻结基准，不重新规划或改写 DESIGN；适配器允许的技术替补继续遵守全新实例、一次业务调用、累计计数和同一路径记录要求。保存路径、命名及最终报告见 [交付](delivery.md)。
