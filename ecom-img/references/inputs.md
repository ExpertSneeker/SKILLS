# 输入与产品基准

本文件是素材来源、缓存、输入选择和最终颜色依据的权威来源。仅规划时也遵守读取边界；可在内存复用或补查获准读取的资料，但不写缓存或其他生产状态。不具备条件时标为草案待补项，不进入生成。

## 拍摄图输入门禁

- 读取产品实拍及进入生成前，`2560px拍摄图/_manifest.json` 必须存在且非空；仅规划缺清单时只用已有获准文字信息，不读取原图。
- 本 Skill 只读取映射中登记的目标文件；禁止读取、查看或传递原始拍摄图路径。
- Manifest 中的 `source_*` 字段属于原始拍摄图信息，禁止查看、回显、记录或派发；只使用 `target_path` 及目标文件所需的非来源元数据。
- 清单和缓存的 `target_path` 均相对于所在的 `2560px拍摄图` 目录，保留子目录并使用 `/`。读取、哈希计算和工具调用时解析为当前绝对路径；拒绝绝对记录路径及越界路径（含链接越界）。下文及适配器所称“登记目标文件”均按此解析。
- 本 Skill 后文的“产品实拍图”“产品实拍”“实拍输入”和“产品垫图”均指当前任务 `2560px拍摄图/_manifest.json` 中登记的目标文件，不指原始拍摄图。

## 产品实拍查看缓存（跨次运行）

- 缓存为 `./2560px拍摄图/_inspection_cache.json`，由主 Agent 保存。`files` 数组保留 inspector 返回的 `target_path`、`sha256`、`facts`、`completeness`、`viewpoint`、`occlusion`、`structure_3d`；字段含义见看图 Agent。只记录产品实拍结果，不写任务绝对路径、原图信息或生成结果。
- 每次运行按“完整相对路径＋实际文件 SHA256＋字段完整”匹配缓存，不为匹配而看图。缓存缺失或损坏视为空，单项无效只补该项；目录位置变化不影响命中。
- 全部命中时直接复用，不启动 inspector。否则将未命中项按 manifest 顺序均分为互不重叠的非空组，组数取未命中项数与当前可用子代理名额的较小值；无可用名额时等待，不另设业务并发上限。每组均以 `agent_type="product_image_inspector"`、`fork_turns="none"` 创建全新实例并行查看，只派发本组未命中项的相对路径、当前绝对路径及 SHA256 和本组 manifest 相对路径清单，不派发有效缓存；模型与推理强度沿用角色配置，不在派发参数中覆盖。
- 主 Agent 待各组结束后汇总结果，逐组核对返回路径属于本组且无重复，成功记录的 SHA256 匹配且字段完整，并检查分配项是否遗漏；无效记录与漏项列为失败项。将各组有效成功记录与有效缓存按完整相对路径合并为当前 manifest 的整体结果，不受返回顺序影响。同次运行后续图号复用，图片变化时仍只补查变化项。
- 只保留当前 manifest 的成功记录；失败或漏项单列，不沿用旧事实，补齐后再锁定完整产品基准。生成模式记录变化时由主 Agent 写入同目录临时文件后原子替换缓存；保存失败保留原文件并报告。
- 缓存仅用于产品基准查看；其他素材及生成 Agent 的当前 direct 实际输入仍按原规则查看。

## 需求与素材读取

- 主 Agent 读取需求表的需求、文案、尺寸、数量、交付类型、内容图型及颜色/SKU；识别 WPS `DISPIMG` 单元格图片并亲自查看、分类。需求表及其他颜色/面料、结构细节、插入或辅助素材由主 Agent 查看，不交给产品 inspector。
- 只补查新增、变化或遗漏的素材，排除生成结果；其他不可读取的 JPG/JPEG/PNG 素材先转码或用可用工具打开，仍不得绕过原图边界。
- 产品身份及商品规格只依据登记实拍、需求表、用户确认和已声明的实际输入；数量未知时不推断多件装。产品实拍查看结果锁定身份、结构、纹理、光泽、比例与禁止偏离项。
- 主 Agent 根据全部产品实拍的查看结果锁定产品真实性底线：产品身份、轮廓、结构、纹理、比例、实拍基准色和禁止偏离项。除非用户、需求表文字或已声明的结构标注素材明确给出，产品形状、轮廓、截面和厚薄关系不得在产品真实性底线或生成提示词中被命名、推断或重述；只用实际输入的 `Image N` 指代并要求保持实拍。手持、按压、弯折、斜放和透视只表示姿态，不得据此定义固定几何结构。

## 反推参考

- 反推专用参考图是可选项；没有时不得阻塞，主 Agent 根据当前图号的销售任务独立规划三个 direct 的场景、构图和卖点视觉表达。
- 反推专用参考图只会出现在需求表中。只有主 Agent 在产品基准锁定后亲自查看并冻结分类，图片才确定为反推专用参考图；不得将其列入实际生成输入、连续 `Image N` 或适配器参数。
- 需求表中带当前产品或竞品产品、用途仅为版式、场景或视觉叙事借鉴，且不承担当前产品身份、颜色/面料、结构细节或插入素材角色的图片，可分类为反推专用参考图；需求表以外的图片不得分类为反推专用参考图，无法确定角色时分类为不使用。
- 只反推版式结构、区域比例、场景、背景、道具、光线、视觉层级、白底或人物是否出现、展示数量、图片表达的卖点意图，以及体现卖点的场景、动作、产品状态、道具关系、对比和真实细节特写等视觉元素；反推的卖点只作为视觉叙事候选，不符合当前产品的功能、结构、功效及其视觉元素不得保留。不得提取竞品产品外观、颜色、面料、结构、Logo、品牌；现成英文和标题/副标题信息层级仅按[设计模块](design-and-prompt.md)及命中平台的文案规则提取。
- 锁定产品真实性基准后、确定各 direct 的其他实际生成输入前，将允许提取的内容改写为独立、具体的反推结果。生成提示词不得提及反推专用参考图、其路径、名称或图片编号，也不得出现“参考/忽略该图产品”等指令。
- 主 Agent 在提示词之外保留 `【内部参考反推记录】`，逐张记录绝对路径、分析角色、反推结果中的版式/场景/展示数量、卖点意图及其视觉元素、现成文案和标题/副标题信息层级，并记录支持或排除该卖点的需求表、用户确认或已核实产品事实来源，以及产品数量、尺寸、形状、结构、颜色、面料和文案等商品规格的真实来源。该记录不得写入提示词文件或派发给生成 Subagent 和生图工具。
- 同一图号有多张反推专用参考图时，优先让不同 direct 使用不同参考图的反推结果，每个 direct 最多分配一张。恰有三张时一版一张；多于三张时由主 Agent 按销售任务匹配度和三版差异化价值选择三张；少于三张时可重复使用参考图。分配结果写入内部记录，数量不匹配不得阻塞。
- 反推的展示数量只用于构图；需求表明确的 `N PC` 或售卖数量始终优先，且不得将反推数量登记为商品规格。

## 实际生成输入

根据当前图号的颜色/面料要求和三版规划，分别为每个 direct 选择实际生成输入。只要当前 direct 的目标画面出现产品，就必须先从 manifest 产品实拍中唯一指定一张完整、无遮挡、整体三维结构清晰且最符合该版产品姿态、视角和构图需求的图片作为该 direct 的 `edit target`，再确定确实需要的其他实拍；三个 direct 可以选择同一路径，也可以分别选择不同路径，不得为了统一而强制复用。其他产品实拍只能承担 `primary product identity`、侧面、厚度、底面、局部结构或按压姿态补充角色，不得再标记为 `edit target`。实拍全部选定后，按该 direct 的产品最终颜色与明确的色块展示需求选择色块，色块去重后，与实拍及其他必需素材一起编排为该 direct 独立、连续的 `Image N`。记录各色块与成图产品/部位及展示用途的对应关系，以及结构细节、插入或辅助素材角色；实际生成输入记录与内部反推记录不得混排。
    - 当前 direct 的目标画面不出现产品时，不设置 `edit target`，也不传入无用途的产品实拍。
    - 无论目标构图最终展示完整产品还是产品局部，`edit target` 都必须先排除主体被裁切、关键结构被遮挡或因视角过平导致整体结构难以判断的图片；优先选择能清晰呈现产品整体轮廓、顶面、侧面、厚度及前后纵深关系的斜俯视三分之四视角（约 30°–45°）。没有该视角时，选择能最清晰、完整呈现产品三维结构的其他合格视角；没有任何合格实拍时阻塞当前 direct。局部或裁切实拍只能作为 `detail/structure` 等补充输入，不能成为 `edit target`；目标构图需要其局部细节时，从完整 `edit target` 构成产品主体，并按需用局部实拍补充该细节。
    - 实拍姿态与目标姿态不同时，在符合上一条完整度和三维结构清晰度要求的候选中，优先选择最接近目标姿态的完整产品实拍作为该 direct 的 `edit target`，并按需加入侧面或厚度实拍；明确旋转后只改变姿态，不重新设计产品。
    - 选图优先级依次为：底图资格和画面适配、按压实拍需求、精修图优先、跨图号分散；后项不得覆盖前项，也不得突破当前工具的输入数量限制。
    - 当前 direct 的目标画面包含按压动作且有对应产品按压实拍时，必须传入该实拍，作为动作、接触关系和受压比例依据。按压状态依据已有实拍查看结果判断，不仅凭目录名或文件名判断；符合上述底图资格时优先作为 `edit target`，否则保留合格完整底图，将按压实拍作为 `detail/structure` 的按压姿态与结构补充输入，明确其用途。没有对应按压实拍时沿用其他选图规则。
    - 根据 manifest 登记的 `target_path` 子目录识别“精修图”“精修”“修图成片”“retouched”等明确表示精修成片的目录，仅用于精修优先级判断，不读取原图或 `source_*`。在满足上述资格及画面需求的候选中优先使用精修图；没有适用的合格精修图时使用普通实拍。
    - 在满足上述优先级的同等适用候选中，结合已有实际输入记录，尽量为不同图号选择不同的 `edit target`；候选不足时允许复用。同一图号的三个 direct 不强制使用不同图片；精修候选不足时允许复用精修图，不为避免重复而优先改用普通实拍。
    - 同一图号的 `direct01`、`direct02`、`direct03` 必须使用相同的目标颜色/面料和已冻结文案。多个独立场景图号有多种颜色/面料可用时，优先在不同图号间分配不同颜色/面料；数量不足时允许复用。
    - 同一张多场景图要出现多个产品，且产品有不同的面料/颜色/印花时，每个场景优先使用不同的颜色/面料/印花；数量不足时允许复用。

`【view_image 实际输入记录】` 属于冻结任务包的内部记录：按当前 direct 的连续编号登记实际输入的绝对路径、角色、用途、来源和已完成的查看情况，不沿用其他 direct 的编号。主 Agent 记录其已完成的检查，生成 Subagent 仍须在自己的上下文查看全部实际输入并另记执行结果；记录不写入提示词文件，也不拼入工具的 prompt。工具输入路径与参数只从冻结调用合同取得。


## 颜色规则

**产品颜色展示**

1. 先按当前 direct 的场景、构图和版式选择 `edit target` 与确实需要的其他实拍，再根据成图中的产品最终颜色选择准确色块，并纳入需求明确要求展示的其他色块；不要求实拍原色配对或原色色块来源登记。
2. 未要求改色时，使用产品保持的颜色对应色块校正实拍拍摄色差；产品结构、纹理和光泽以实拍为准。
3. 要求改色时，只使用改色后的目标色块决定最终颜色，不为实拍原色另传色块。
4. 产品最终颜色所需色块缺失时阻塞当前 direct；要求改色但缺少目标色块时阻塞当前图号。无需为未出现在成图中的原色额外传色块；保持原色时，它就是最终颜色，仍必须提供对应色块。不得根据实拍观感、近似色或颜色文字猜色。纯展示色块缺失按下方“色块素材缺失”处理。
5. 相同的最终颜色可以共用一张对应色块，实际输入去重后只传一次，并记录各色块对应的成图产品/部位或展示用途。
6. 色块默认只作为产品颜色依据，不得改变文字的视觉基准，也不得作为可见元素生成；只有需求明确要求展示色块时才在画面中呈现。

**色块展示**
> 此规则在生成符合条件图片的提示词中体现。

- 普通图片的色块不得显示颜色编号，包括颜色代号、Color ID 和 SKU 色号；普通副图可以保留需求表提供的颜色名字。明确要求的色号图或定制模板按定制模块的专用规则执行。
- 主图要求添加色块时，色块必须直接叠加在背景图或场景图上，色块组与背景之间不得增加承载卡片、底板或底色；主图色块不得显示颜色编号或颜色名字。

**色块素材缺失**

需求表要求放置色块，但没有找到全部颜色编号对应的实际图片时，仅使用已有颜色图占位。

同一 direct 中提示词的 `Image N`、实际输入顺序与工具参数必须一致；生成子代理在自己的上下文查看所有实际输入，不能用上游查看或缓存记录冒充本次查看。
