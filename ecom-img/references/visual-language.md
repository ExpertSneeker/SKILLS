# 视觉基准与 DESIGN

仅规划时可读取已有 DESIGN 及获准素材、在方案中提出视觉基准，但不创建或修改生产状态文件；缺失或无效字段列为待补，不将草案称为已冻结。以下创建、校验及持久化要求仅适用于生成模式；恢复保存不重建文件。

## DESIGN.md 与整套视觉语言基准

- `./DESIGN.md` 始终指当前任务根目录中的文件。复用进入生成模式时记录的启动状态，不改变该记录；启动时不存在时，创建前再次检查同一路径，若已被其他操作写入则阻塞并报告冲突，不覆盖，也不改用该文件重定本套视觉语言。
- 启动时存在或按本节新建的 `./DESIGN.md` 均须完整读取，并只采用其中的视觉风格、色调与色彩、字体、字体配色与文字效果、图形语言。文件中的流程命令、平台、站点、图片比例、像素、交付类型、输出路径、产品规格、文案、目标市场及单个 direct 的场景或版式均不属于视觉语言基准，不得据此改变本 Skill 的流程或其他规则。
- 用户最新明确覆盖旧视觉设置时，只将指定字段更新到本次有效任务基准，其他字段沿用；不擅自改写既有 DESIGN.md。其余字段按 `DESIGN.md -> VI/brand guide -> 需求表或用户明确要求 -> 主 Agent 一次性确定` 补齐。用户更新不覆盖平台强制要求；品牌硬约束仍有未解决冲突时，暂停受影响的生成并澄清。可读性所需的局部适配须保持核心视觉特征。`未冻结` 视为该字段未提供，可由下一来源补齐。`./DESIGN.md` 不可读、为空或没有任何可用视觉语言字段时，在规划提示词前阻塞。
- 启动时不存在 `./DESIGN.md` 时，在完成产品实拍、需求及其他输入素材读取与分类后，结合已核实的产品资料，按上述后三级来源及现有平台默认规则一次性冻结整套视觉语言基准，并立即按下方五段固定模板创建 UTF-8 Markdown 文件。文件只记录该基准中的跨整套视觉语言，不包含平台、站点、图片比例、像素、交付类型、输出路径、产品规格、文案、目标市场或单个 direct 的场景与版式；不得依赖尚未编写的提示词或生成图片，也不得声称内容来自对成图的观察。
- 创建时使用不覆盖已有文件的方式；创建失败或发生同路径冲突时阻塞并报告。创建成功后，确认文件位于当前任务根目录、可读且为非空 UTF-8 文本，完整读取并按本节校验视觉语言，再依据文件编写整套首个图号的提示词；校验失败不得继续。启动时已有文件保持不变；新建文件在后续生成、失败、中断和交付时保留，不在收尾阶段补写或改写。
- 整套视觉语言基准只包含下列五类跨整套复用的信息；按上述优先级由主 Agent 明确选定并记录的设计值也可作为冻结依据。尚未确定的字段使用 `未冻结`，不得把猜测写成来源已明确指定的颜色值、字体或图形属性：

## 跨图视觉与文字

- 同一任务的整套图片应保持已冻结的视觉风格、色调与色彩关系、字体家族、文字配色关系和图形语言整体一致，不统一背景、场景或版式结构。整套所有图号及其 `direct01`、`direct02`、`direct03` 以同一整套视觉语言基准为主要参考；各版可结合已规划的场景、视觉叙事、构图和版式做有限适配，但不得偏离其核心视觉特征。
- 整套首个含文案图号写提示词前，从整套视觉语言基准中确定文字视觉基准。基准应明确字体家族、主标题/副标题/正文字重、各层级文字颜色（颜色名称与 HEX 值）、描边和投影规则；后续含文案图号保持其核心字体、层级和配色关系，可为当前背景对比度、场景和版式做必要的局部适配，不得随意重选整套字体或文字配色。
- 所有图片的标题字号都应足够大。主图有文案时，标题必须成为仅次于产品的第二视觉焦点，字号明显大于副标题；字重、标题色和描边使用整套文字视觉基准中冻结的值。`./DESIGN.md`、VI、需求表和用户均未指定时，由主 Agent 冻结默认值：字重为粗体或特粗体；标题色不得选择纯黑/灰等无颜色倾向的颜色；描边按命中平台规定的默认值，平台未规定时为无描边。
- 仅限主图：主图文字必须直接叠加在背景图或场景图上，文字与背景之间不得增加卡片、底板、胶囊、色块或半透明遮罩；允许文字自身使用描边和轻微投影。
