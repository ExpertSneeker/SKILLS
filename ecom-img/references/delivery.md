# 直接保存与交付

## 制作规范

- 生成结果保留当前生图工具的原生尺寸。
- 交付类型和目标构图比例只由唯一命中的平台规范提供；场景图、尺寸图、卖点图、颜色图、SKU 图、规格图等是可出现在任一受支持交付类型中的内容图型。按用户或需求表分别确认两者，不得仅凭内容图型把图片归为副图。
- 产品尺寸单位按唯一命中的平台规范、用户要求和需求表冻结；需求表已有明确单位时按需求表执行，图片内表达必须自然、统一、易读，不得从另一平台借用默认单位。

**路径**

- ImageGen 直接生成图片和来源清单：`./output/gpt-images-2-direct`
- Seedream 直接生成图片和调用记录：`./output/seedream5-pro-direct`
- 技术失败隔离位置：按当前工具适配器或工具自身 skill 执行
- 生成结果必须保存到上述当前工具的直接生成目录，不得只留在工具全局默认目录或临时目录
- 在 Windows 中文目录中处理图片或表格时，使用 Unicode 安全的绝对路径和文件 API；不要通过会丢失编码的管道或通配符把中文文件名传给脚本。出现 `????` 路径时，先修复读取方式再继续

**命名**

- 直接生成图：`序号_产品名_图类型_direct01.png`、`序号_产品名_图类型_direct02.png`、`序号_产品名_图类型_direct03.png`；序号使用两位数字补零并置于文件名最前面，以便按文件名排序。
- 示例：`02_YY006_场景图_direct01.png`

## 直接保存规则

- `direct01`、`direct02`、`direct03` 生成成功后分别直接保存并标记 `SAVED`，三版全部作为交付结果保留。
- 单版生成 Subagent 返回后，主 Agent 和其他 Agent 均不得查看生成图片；只允许核对文件存在性、可读取性、比例尺寸、哈希、路径和调用记录。
- 不比较或挑选三版，不创建 `./output/final`，不生成 `_v01`，不做生成后缩放、局部修改、文字覆盖或本地修图。
- 图片内容问题不得触发重新生成；文件级技术失败按生成模块及工具调用记录判断能否恢复或技术替补，不能仅因缺图重新生成。

## 完成报告

完成级别按 [生成流程的状态与结束条件](generation-workflow.md#状态与结束条件) 判定；报告计划、SAVED、最终失败及待核实数量。处理完全部项目不代表全部成功，技术失败不得计入交付成功。

DESIGN 生命周期只按 [视觉基准](visual-language.md)；交付阶段不创建、改写或覆盖，失败和中断也保留已创建文件。

## 交付核对

复用生成阶段已有且未变化的文件确认；只补查新增、变化或缺失的记录。平台交付检查核对冻结提示词、任务包与非视觉文件信息，不查看成图，也不宣称已视觉验收。

- [ ] 每个图号三个 direct 的保存或失败/待核实状态均有记录，报告准确区分完整交付与部分交付
- [ ] 每个已保存文件可读取并已记录比例尺寸，且有完整、唯一的路径、哈希和调用记录
- [ ] 三版均保留原始 direct 文件名和工具原生尺寸
- [ ] 已执行唯一命中平台文件中的“交付检查”，且未读取或混入另一平台规范
- [ ] `./DESIGN.md` 已在提示词编写前完成读取或创建并校验，交付阶段保持不变
