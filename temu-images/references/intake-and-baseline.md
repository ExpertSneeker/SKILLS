# 素材读取与证据基准

本文件定义如何读取证据并判断开工门槛。强制门槛以 `SKILL.md` 为唯一清单；这里不提供任何绕过路径。

## 1. 盘点产品文件夹

以用户指定的产品文件夹为任务根目录，递归盘点但不修改原文件。先按以下两类登记，禁止把“条件性素材”误解为“存在也可忽略”。

### 必需素材

- 需求表：优先 `.xlsx`、`.xls`，同时识别用户明确指定的其他结构化表格。
- 产品实拍图：必须能清楚判断真实结构、边缘、厚度、缝线、面料、颜色和比例中与本任务有关的项目。
- 尺寸证据：记录原始尺寸文字、单位、适用 SKU/部位及来源文件、工作表和单元格；不能只记录换算结果。
- 输出类型：主图或副图主题。需求表中的详情、详情页、SKU、颜色图、规格图、尺寸图、卖点图统一归为副图主题，除非用户另行指定。

缺少需求表、真实尺寸、清晰产品实拍图或输出类型中的任意一项，任务立即阻塞；不得先做预览、模板或假定版本。

### 条件性素材

- VI/brand guide、logo 规范。
- 面料图、色卡图、颜色代号图和颜色文字证据。
- 产品细节图、SKU 图、版式参考、场景参考、插入素材、禁用信息及其他逐图参考。
- 需求表内或附件中的 WPS `DISPIMG` 嵌图。

某类条件性素材不存在时，登记 `not_available` 或等价明确状态，不因缺失本身阻塞。只要文件、嵌图或明确引用存在，就必须读取、检查并登记适用范围；不得因它不是通用开工必需项而跳过。存在但不可读的素材按第 2、4 节处理。

### 素材检查职责

主 Session 负责目录盘点、表格结构读取和证据汇总；所有图片素材由素材检查 Subagent 逐张执行 `view_image`。检查记录必须包含 `inspection_session_id`、`checked_at`、`notes`、素材角色和适用图号。主 Session 自己查看、生成 Subagent 在调用前重新查看，都不能替代素材检查 Subagent 的记录。无法创建素材检查 Subagent 时任务阻塞。

所有记录使用 Unicode 安全的绝对路径。Windows 中文路径出现 `????`、文件名截断或无法往返读取时，先修复读取方式再继续；不要通过可能丢失编码的管道、通配符或字符串拼接传递路径。

## 2. 恢复不可读图片

普通产品图、VI、面料/色卡和参考图无法读取时，先在不修改原文件的前提下依次尝试：用兼容查看器打开、用结构化图片库验证格式、无损转码或转换色彩模式到 `output/temp/<task-id>/intake`、再由素材检查 Subagent 对转换副本执行 `view_image`。记录原路径、转换路径、原始/转换格式和结果；不得通过改扩展名伪装格式。所有合理读取路径都失败后，只要素材可能影响产品、颜色、尺寸、文案、VI、版式或任一图号，或无法用其他可靠证据证明其与全部图号无关，就按不可读关键素材阻塞；不得仅凭文件名、经验或进度压力把未知内容判为无关。

## 3. 读取需求表

使用可保留单元格类型、公式、工作表和嵌入对象关系的结构化表格工具或 Office/WPS 应用读取，不得只复制屏幕上可见文字。逐项记录：需求、逐图参考、英文原文文案、尺寸、输出类型、颜色/SKU、卖点、禁用项和备注。

需求表是业务要求的首要来源，但不能覆盖平台合规和产品真实性。若需求表、平台规则和用户口头要求冲突，记录具体冲突并阻塞，等待用户处理；不要自行改写成另一个方案。

## 4. 处理 WPS `DISPIMG`

发现 `DISPIMG` 公式、占位符或疑似单元格图片时，必须完成以下闭环：

1. 优先用能显示 WPS 单元格图片的 WPS/Office 工具打开并导出。
2. 若需解析 `.xlsx` 包，使用 ZIP、XML 和关系文件的结构化解析器，检查 `xl/cellimages.xml`、对应关系文件和 `xl/media`，把公式中的图片标识映射到工作表和单元格；禁止用正则或文件顺序猜映射。
3. 将相关嵌图无损导出到 `output/temp/<task-id>/intake`，记录工作簿、工作表、单元格、图片标识和导出绝对路径。
4. 由素材检查 Subagent 对每张导出图片执行 `view_image`，记录检查 Session、时间和结论并标为 `completed` 后才能使用。

在成功查看前，任何不可读 `DISPIMG` 一律视为关键素材，因为无法用未知内容证明它与任务无关。可靠查看并记录后，只有明确与本产品和全部图号无关的嵌图才可排除。无法可靠映射、导出或查看时任务立即阻塞；负责人要求跳过、截止时间或已有投入都不是例外。

## 5. 建立产品与面料基准

首次规划提示词前，在 `_temu_job.json` 中建立：

- `product_baseline`：强制产品输入的绝对路径、实拍角度、尺寸来源、适用 SKU，以及默认必须保持的结构、面料、颜色、纹理、缝线、边缘、厚度和比例。这里只记录证据约束；逐图确有颜色变化时，必须另由 `allowed_product_changes` 明确列出依据和范围，其他属性继续锁定。
- `fabric_baseline`：面料/色卡证据、适用颜色或 SKU、证据来源和禁止偏离项。没有独立面料证据时明确写 `not_available`，不得伪造。

参考图与实拍图冲突时，产品/面料实拍证据优先。版式、场景或氛围参考没有定义产品外观的权限。

## 6. 颜色证据规则

颜色展示只按以下顺序使用证据：

1. 当前产品实拍图中的真实颜色。
2. 与目标颜色明确对应的面料图、色卡图或颜色代号图。
3. 需求表或文件名中的明确颜色文字。
4. 以上均无时，颜色展示区域留白，只规划版式和已提供文案。

每次颜色变化必须映射到明确的目标图号和 SKU，并写入该图的 `color_evidence` 与 `allowed_product_changes`；未登记的图片保持实拍颜色。颜色文字只能支持该名称的语义色相，不支持自行指定 HEX、RGB、明暗层次、混色、纹理或光泽。用户确认时必须明确提示“只有颜色名称、无法保证精确色差”；若任务要求精确颜色，缺少对应实拍/面料/色卡就阻塞。竞品/版式参考中的颜色不能作为本产品颜色依据，证据互相冲突且需求表不能裁决时也阻塞。

## 7. 建立统一视觉基准

`visual_baseline` 从 VI、需求表、产品证据和获准参考中归纳：

- 系列配色及其证据来源。
- 字体类别、字号层级和 logo 使用规则。
- 背景、光线、构图密度、图标语言和移动端信息层级。
- 场景价格感、用途和目标用户。
- 全系列必须保持一致的元素及每图允许变化的元素。

若有 VI 则严格遵守。没有 VI 时可以规划柔软、温暖、清楚的视觉系统，但不得由此新增品牌资产、产品属性、认证或卖点。

## 8. 读取结果

读取完成后，把每个证据写入 `_temu_job.json.evidence_sources`：绝对路径、SHA256、`media_type`、来源位置、证据角色、素材检查 Subagent 编号、是否已执行 `view_image`、检查时间、观察结果和适用图号。同时填写 `material_inventory.required` 和 `material_inventory.conditional`，确保所有证据恰当归类；条件性素材不存在时保留 `not_available`。仍有未解决门槛时，`job_status` 保持 `blocked`，只向用户输出阻塞清单；全部必需素材和所有已发现的相关素材处理完成后才能进入任务规划与用户确认。
